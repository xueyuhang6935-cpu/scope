## 行为与设计说明

- 范围、批次、时点与证据由已保存运行和后端快照确定，不接受客户端权限覆盖。人工陈述保持未经验证；分析约束仅改变确定性内部建议，不改写源数据或自动恢复已停止模型。
- 待审建议绑定快照指纹、报告和任务证据，保存内容摘要与版本。新增反馈使旧待审版本失效；驳回原因留在历史，新建议必须改变内容；审核核对最新状态和摘要。发起人即使有审核角色也不能自批。
- 操作在现有 SQLite 事务与单进程锁内落盘；最后一个相同操作可幂等重读，旧版本不同操作返回冲突。后续操作持续复核当前角色与区域权限；审核权被撤回后不能据旧批准创建内部单。
- 批准与内部跟进分开；内部单不调用外部派单 API。默认回执标为模拟，人工报告真实回执须有来源编号，仍标记待外部核验。无回执不能复核。
- 新快照必须同批次、城市、区域、源版本和指标口径，时点更晚且原可见队列不能消失。旧风险和新流入分别计算，完整统计与前20条展示区分；不将历史完成归因于内部建议或模拟回执。
- 演示限制为每运行最多50条反馈、20版建议，一张内部单、一次回执及一次复核。尚未接正式 ContextBuilder、物流审核 LangGraph 中断恢复或聊天发送；不宣称正式阶段验收完成。
- 启动前通过 SQLite backup API 保存三份本机数据库至 `data/backups/logistics-demo-20261011-201201/`，完整性均为 `ok`。随后重启原本机后端，保留单应用进程，未重导或修改 PostgreSQL 源表，未更改角色或配置。
