## 修改摘要

所有模型工具在执行前及交付前复核调查权限和范围，缓存方案、报告引用和报告落库使用同一授权检查。权限或范围失效立即转人工。工具记录独立于调查报告即时保存，恢复时保留完成记录并标记中断调用。

## 变更文件

- 新增 `backend/investigation_harness.py`：缓存证据及方案授权、即时调用审计、记录读取与中断标记。
- 修改 `backend/investigation_agent.py`：统一工具入口检查，调用前后审计，报告提交复核，拒绝未经授权的结果交付。
- 修改 `backend/supply_workflow.py`：复用调查授权函数，落库前复核与权限锁，异常及重启中断标记，受权限约束的审计查询接口。
- 新增 `backend/test_investigation_harness.py`：撤销成员权限、缩小工厂／数据域范围、修改回放范围及持久化恢复测试。
- 修改 `backend/test_supply_workflow.py`：报告落库前撤权测试与真实模型模拟流程的审计查询验证。
- 修改 `docs/investigation-sql.md`：记录统一检查、审计存储、接口及保守授权契约。

## 行为与设计说明

- 调用审计存入现有业务 SQLite 的 `investigation_tool_calls`，首次初始化自动建表，无新增依赖。调用前保存参数，授权后执行前保存范围，结束后保存结果、错误与耗时。
- 状态为 `started`、`completed`、`failed`、`interrupted`。恢复不重放模型调用。
- SQL 证据的原数据域／工厂范围不得超出当前授权。间接所属的缓存证据保守要求整个调查工厂范围的对应数据域权限；方案动作检查来源及目标工厂的五类业务数据域。
- 单进程内，报告授权复核与 PostgreSQL 提交保持业务权限锁，防止中间插入权限修改。此锁不提供多进程一致性保证。
- 新增 `GET /api/supply/investigations/{id}/tool-calls`，检查当前工厂查看权限及记录涉及的数据域权限。
- 未改变 SQL 白名单、确定性方案计算、审批业务执行边界及模型收费重放策略。
