# DeepSeek动态调查与恢复

## 使用

在“订单与支付分析”选择14天演示快照、分析类型“动态异常调查”，指定目标2026-09-29、基准2026-09-28，包含支付率指标。也可输入“调查9月29日和28日支付率下降”。普通查询继续走确定性短路径；自然语言范围解析仍为保守规则，不是通用大模型解析器。

Scope/.env 使用 `ANALYST_MODEL_BASE_URL=https://api.deepseek.com`、`ANALYST_MODEL=deepseek-flash`、`ANALYST_MODEL_API_KEY`。支持以 DEEPSEEK_API_KEY 代替密钥变量。不要将.env提交或发到聊天。服务启动时加载配置，更改后重启服务。

已核对官方文档：<https://api-docs.deepseek.com/> 与 <https://api-docs.deepseek.com/api/create-chat-completion>。当前接口列出deepseek-flash与deepseek-v4-pro。适配器显式使用非thinking模式，避免隐藏推理字段回传要求；使用原tool_call_id逐项响应，读取usage.total_tokens。不把模型原始自由文本当作已核验报告。

一次改进上下文后的真实调用完成调查：3次模型请求、15,768个返回Token，用量已知。模型实际选择渠道/设备分组、交叉过滤和错误检查。首次联调因上下文冗余触及预算，2次请求返回9,931 Token，已如实保存在运行时记录中。两次合计已记录25,699 Token；金额未计算，以DeepSeek账单为准。这是功能联调，不是独立保留集或B1/B3评测结果。

## 动态策略与边界

宿主先加载定义、检查就绪、做总体比较；变化小于2个百分点且没有指定分组检查时确定性停止。否则模型选择受控分组、交叉比较、错误检查与样例工具。固定日期、快照、指标与根过滤不可由模型扩大。模型只提交当前任务证据引用和停止类型；事实数值从已提交证据确定性生成。完整分组证据与用户指定维度检查通过后，才能标为定位完成。

当前完成表示已交付描述性定位，不表示确认业务根因。错误与时间线在“执行证据”中查看；运行时报告不接受模型自行编写的因果解释。完整V3结构化候选解释、反例管理和公平对照仍待后续扩展。

## 检查点与恢复

Node在调用Python前保存作业与请求编号；Python使用独立outputs/runtime/runtime.sqlite保存模型尝试、原始协议消息、pending工具、结果与预算。单会话SQLite锁在进程退出后自动释放。已完成工具结果、逻辑证据与检查点同事务保存；已提交模型响应先恢复pending队列，不重新请求模型。

网页出现中断时，点“重新载入会话”，再点“恢复任务”。同一请求ID与task_id恢复；新会话不能冒充旧任务恢复。日期/快照哈希/注册表/模型/提示词或工具版本改变时拒绝恢复。

预算：任务180秒、12次工具请求、16次执行尝试、10次模型请求、20,000已用加预留Token；会话100,000已记录Token。预估不等于严格账单上限。恢复不延长原期限、不重置预算，过期任务输出已有结果。工具未提交尝试记录unknown，允许最多一次只读重做；模型请求结果或账单未知时保守停止，不盲目重发。显式429最多重试一次。鉴权失败不重试。

注意：不能承诺恰好一次查询或计费；模型调用期间网络断开可能已产生费用。已完成回放不调用模型。恢复支持是本地单进程原型，不是分布式工作流。
