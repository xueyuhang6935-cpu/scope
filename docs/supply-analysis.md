# 供应链分析接入

当前助手已连接 FastAPI `/api/supply/*`，支持授权工作空间内的导入库存查询、质量问题分析；保存 PostgreSQL 场景后，缺料问题调用确定性计算服务，返回首次缺料、缺口、受影响计划和来源证据。明确且受支持的只读查询直接执行，并展示实际范围。只有信息缺失、范围冲突、不能可靠识别或超出当前能力时才追问。未配置缺料计算场景时提示先接入数据或改为库存、质量查询。业务审批仍保留，不会通过聊天自动执行采购、审批或调拨。详见 [缺料计算与风险监测](shortage-monitoring.md)。

## 启动与使用

运行 `npm run dev`；生产预览先运行 `npm run build`，再运行 `npm start`。已运行且没有自动重载的后端需要重启。开发代理仍使用 `SCOPE_API_PROXY_TARGET`，默认端口为后端 3002、前端 3003。

1. 用同一个账号在数据中心导入库存文件并提交；质量问题可隔离保存。
2. 打开智能助手，输入“查询 P001 库存”或“检查当前工厂数据质量”。
3. “查询 P001 库存”“检查数据质量”等明确查询发送后直接执行；结果默认展开当次工厂、物料和时间范围。已接入场景时，“检查 P001 未来三天缺料风险”也直接执行，额外显示场景、证据截止时间和计算窗口。
4. 需要澄清时，页面列出具体问题，调整字段后点击“按此范围查询”，或停止任务并改写问题。多物料、排除条件、自定义日期等无法表达的条件不会被静默丢弃。未指定物料表示全部物料，未指定工厂沿用会话范围，缺料窗口未指定时沿用已捕获的场景配置。
5. 回答展示当次范围、数据读取时间、记录编号、来源批次及限制。刷新页面可恢复历史结果和仍在执行的任务。

文件导入数据尚不具备完整生产需求、占用和承诺结构，未配置数据库时，缺料请求会提示补充数据来源。数据库场景使用已接入的完整模型计算；存在缺失的物料仍输出不可计算，不把记录缺失当作零库存。场景、回放时点和窗口在提交问题时记录，并在实际执行范围中展示；后续场景改变会要求重新发起。

## 可选模型解析

在服务端 `.env` 显式配置后重启后端：

```dotenv
SUPPLY_PLANNER=model
SUPPLY_MODEL_BASE_URL=https://api.deepseek.com
SUPPLY_MODEL=填写供应商当前支持的模型名称
SUPPLY_MODEL_API_KEY=填写服务端密钥
```

密钥也可使用 `DEEPSEEK_API_KEY`。默认 `SUPPLY_PLANNER` 非 `model` 时不请求模型，不自动使用旧订单分析配置。不要使用 `VITE_` 前缀保存密钥。

常见明确问题使用规则直接解析和执行，即使已配置模型也不为这些问题发起解析请求。其余表达可由模型辅助解析，模型只收到问题和手动范围，不收到原始业务表。返回字段之外还须返回 `clarification`：范围明确且全部条件受支持时为空，否则填写具体追问。宿主再次检查能力、显式条件、范围冲突和授权；校验通过才自动执行，不能仅凭模型声称“已理解”忽略原条件。

请求禁止重定向，设置30秒网络超时、800输出 Token 和响应体大小限制，每个任务最多调用一次；超时或无有效响应不自动重试，转为待澄清。用量已知时保存并展示，未知时不当作零。停止不能撤销已发送的模型请求或已经发生的费用。测试使用模拟传输，没有进行收费模型调用。

## 接口约定

所有接口使用已有登录 Cookie，按用户校验会话和任务所有权。写入接口校验请求来源；生产跨域部署需设置 `FRONTEND_ORIGIN`。

| 接口 | 用途 |
| --- | --- |
| `GET /api/supply/capabilities` | 能力与解析模式 |
| `POST /api/supply/threads` | 使用 `factory`、`requestId` 幂等创建会话 |
| `GET /api/supply/threads?factory=A` | 当前账号最近 100 个匹配会话 |
| `GET /api/supply/threads/{id}` | 会话和任务消息历史 |
| `POST /api/supply/threads/{id}/messages` | 使用 `text`、`scope`、`requestId` 提交问题 |
| `GET /api/supply/tasks/{id}` | 轮询任务状态与结果 |
| `POST /api/supply/tasks/{id}/confirm` | 仅用于待澄清任务，提交 `plan`、`confirmed:true` 后按调整范围查询；相同已提交范围保持幂等 |
| `POST /api/supply/tasks/{id}/cancel` | 停止交付后续结果 |

`scope`/`plan` 包含 `intent`（inventory/quality/readiness）、`factory`（all/A/B）、`material`（单个精确编码或空）、`supplier`、`period`。供应商条件、库存/质量查询的时间筛选、超过14天的缺料窗口等会在执行前追问；澄清提交仍含不支持的结构化条件时返回400，不读取近似结果。具体工厂会话禁止改变成其他工厂或全部工厂。

`planning.questions` 持久化具体追问，`planning.execution` 区分 `automatic`（直接执行）与 `clarified`（澄清后执行）。两条路径共用权限、能力及队列检查，实际执行与交付结果时仍复核授权。业务审批编排和角色校验不受本改动影响。

状态为 `planning`、`awaiting_confirmation`、`queued`、`running`、`completed`、`insufficient_data`、`no_data`、`failed`、`cancelled`。相同请求编号与相同内容返回已有任务；内容改变返回 409。同会话只允许一个待确认或执行中任务，每会话最多 100 轮，全局最多接受 16 个解析/执行任务。

## 存储与边界

新增 `supply_threads`、`supply_tasks` 到现有供应链 SQLite，启动时自动建表并兼容添加模型解析记录列。会话和证据结果持久化，后续导入或治理不会改写历史回答。库存证据使用已标准化数量，算法口径版本为 `supply-readonly-v1`，它不是单位换算规则的版本号；现有源记录未保存所用换算规则 ID，精确换算规则版本追溯仍需扩展导入存储。

库存与质量分析只读取当前账号导入的当前版本记录及该账号导入产生的质量问题；缺料计算读取提交问题时确定的 PostgreSQL 模拟场景、回放时点和窗口。原文件数据中心仍为登录用户共享数据视图，没有将其改为企业角色权限系统。当前导入记录按工厂和物料共享更新，同一业务键被其他账号更新后，旧记录不会被分析为当前库存。

文件查询每次最多返回 200 条证据，显示是否截断；库存按物料分别列出，不跨物料相加。文件只读查询与现有导入写入共用锁获取一致快照；模拟数据库计算使用 PostgreSQL 可重复读事务和业务获知时间过滤，保存完整的场景证据。助手仍使用单进程、两个任务线程，不支持多 Uvicorn worker；扩大部署前需改为任务租约和独立工作进程。重启后中断的助手解析/执行任务标为失败，不自动重放收费请求。风险监测是独立的单线程定时扫描，重启后根据持久配置继续检查。取消不能中断已开始的查询，但取消状态会阻止结果提交。30 秒分析期限在交付结果前检查，不是数据库硬中断；PostgreSQL 单条语句另有 5 秒限制。
