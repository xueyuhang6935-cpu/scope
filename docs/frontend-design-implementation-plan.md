# Scope 桌面端页面改版实施建议

- 整理日期：2026-10-13。
- 文档性质：实施建议，尚未实施，不代表已经完成接口接入或页面验收。
- 后续实施状态：2026-10-13 已按共享快照、工作台布局、指标中心与配置、任务接口、业务专题、验收的顺序完成本次改版；原建议保留，实际交付与验证见第 10 节。
- 设计依据：已确认的工作台、指标中心及首页指标配置设计预览。
- 本期范围：桌面端工作台重组、指标中心、首页指标配置，以及这些页面需要的数据能力。
- 实施原则：优先复用现有 React、路由、请求封装和后端计算，不新增无必要的框架、依赖或通用指标引擎。

## 1. 目标与设计参考

首页优先展示当前范围、核心指标和重点任务，通过业务专题、指标中心及用户配置承接后续增长的业务指标。

首页默认展示四项指标，但四项不是系统指标数量上限，四列也只是桌面布局规则。业务指标增加时，通过指标目录、分类和搜索扩展，不要求持续修改首页结构。

### 2.1 工作台布局

建议按以下顺序组织内容：

1. 页面标题与主要操作：配置首页指标、发起调查。
2. 紧凑范围栏：区域、参考时点、快照状态、范围说明。
3. 核心指标概览：展示用户选择的指标及“查看全部指标”入口。
4. 主内容区：左侧优先任务，右侧待办事项与最近调查。
5. 业务专题入口：风险与积压、揽收时效、人员负荷、字段质量。

长流程介绍和详细限制说明放入可展开的“范围说明”。“历史回放”“参考年份未知”等必要提示保留在范围栏附近。

发起调查继续沿用当前确定性调查与实验模型调查的选择规则。按钮应带入已生效快照；未生成快照时明确提示先完成范围设置。

### 2.2 视觉与桌面适配

- 保留紫色主色，统一间距、字号、边框、圆角和按钮层级。
- 为风险、待审核、已驳回、不可计算等状态统一文字标签和颜色，不仅依靠颜色传递含义。
- 新增样式使用物流页面专属类名，控制对其他页面的影响。
- 首期主要检查 1280、1440、1920 像素桌面宽度，避免整页横向溢出、任务表格挤压和操作按钮遮挡。
- 保留必要的窄屏可用性，本期不另行设计独立手机页面。

## 3. 建立可扩展的指标目录

### 3.1 复用现有五项指标

当前工作台写死三张卡片，后端汇总已经提供五项指标：

| 稳定 ID | 展示名称 | 建议分类 | 默认首页展示 |
| --- | --- | --- | --- |
| `backlog` | 样本内积压 | 风险与积压 | 是 |
| `overdue` | 逾期未完成 | 风险与积压 | 是 |
| `due_soon` | 临期未完成 | 风险与积压 | 是 |
| `recent_accepted` | 近期接单 | 揽收时效 | 否，可配置 |
| `recent_completed` | 近期完成 | 揽收时效 | 是 |

原型中的 `due`、`accepted`、`completed` 等简写，正式实现时统一使用后端稳定字段，避免维护额外映射。

### 3.2 指标定义与展示

建议先维护一份简单的共享定义列表，记录稳定 ID、名称、分类、单位、说明、展示类型、是否可加入首页及查看方式。

首页和指标中心共用这份定义，数值由后端返回。统计窗口、数据状态、口径版本及权威计算规则以服务端契约为准；前端说明应与对应版本保持一致，不能自行计算权威业务指标。

指标中心支持分类、按名称与说明搜索、查看口径、加入首页及移出首页。首期完整目录较小时可以在前端搜索目录；业务任务记录的跨页搜索另由后端实现。

首页按用户选择顺序渲染。选择较多时允许网格换行，并提示保持首页简洁；指标总量由指标中心承接。

## 4. 区分数值指标与业务专题

| 类型 | 示例 | 建议展示与交互 |
| --- | --- | --- |
| 数值指标 | 积压、逾期、近期完成 | 数值、单位、统计窗口、数据状态和口径入口 |
| 业务专题 | 人员负荷、可见字段质量 | 专题摘要、说明及进入专题的按钮 |

当前卡片点击行为关联待揽收任务筛选。扩展后应为每项定义明确入口：

- 积压、逾期、临期：进入对应任务清单。
- 近期接单、近期完成：进入对应时间窗口明细；明细接口未接通时先提供口径查看。
- 人员负荷：进入按快递员分组的专题。
- 字段质量：分别展示窗口、位置、GPS 等字段统计，不合并为未经定义的单一质量分数。

人员负荷只表达当前样本中的任务与风险分布，不据此判断真实人员容量、责任或因果。

## 5. 共享当前快照与数据状态

工作台和指标中心应共享区域、参考时点、`snapshot_id` 及当前快照元数据。页面切换后继续查看同一份授权结果。

建议明确区分两组状态：

- 正在编辑的区域和参考时点。
- 已生效快照对应的区域和参考时点。

修改范围后必须更新快照才生效。创建中、失败或输入变更时，不得让旧数值看起来属于新范围。账号、空间或授权版本变化时，需要清理旧上下文并重新校验读取权限。

可以通过现有路由和少量共享状态实现，不必引入新的全局状态管理库。

卡片至少区分以下情况：

| 状态 | 建议表现 |
| --- | --- |
| 正常值为 0 | 显示 `0`，表示该口径下结果确实为零 |
| 未生成快照 | 显示待生成提示和范围设置入口 |
| 加载中 | 显示加载状态，避免与正常结果混淆 |
| 读取失败 | 显示失败说明和重试入口 |
| 不可计算 | 显示原因；后端提供下界时展示“已知至少……” |
| 空样本 | 明确当前样本为空，不能推断整个区域没有风险 |

## 6. 首页指标配置

配置弹窗建议支持勾选、取消、调整顺序、恢复默认、保存及取消。排序首期使用“上移／下移”按钮即可。

配置编辑使用草稿状态，保存后才更新首页，取消时丢弃本次修改。沿用预览的至少保留一项规则。

首期可以使用浏览器本地存储，按账号和空间区分，只保存指标 ID 与顺序。加载时过滤已经移除或当前不可用的条目，并在无有效选择时恢复默认。

本地保存仅覆盖当前浏览器。需要跨设备同步时，再增加后端用户偏好读取与保存接口。配置不保存业务数值，也不替代服务端授权。

## 7. 数据接口复用与补齐

| 设计区域 | 当前基础 | 建议补充 |
| --- | --- | --- |
| 核心指标 | summary 已返回五项指标 | 复用现有汇总接口和口径 |
| 优先任务 | tasks 已有风险排序及分页 | 补充跨页搜索、风险集合筛选和任务证据入口 |
| 人员负荷 | groups 已有快递员分组 | 首期展示积压、逾期、临期；近期流量分组另补 |
| 字段质量 | 工具层已有字段统计逻辑 | 复用计算，提供经过授权的页面读取能力 |
| 最近调查 | 已有调查列表 | 展示最近几条授权记录，并链接到真实详情 |
| 待办事项 | 已有审批与协同状态 | 增加按当前账号、角色汇总的计数与列表能力 |

### 7.1 风险集合与搜索

当前 tasks 的 `all` 包含普通待揽收任务，设计图中的“全部风险”则应只包含逾期与临期。建议后端提供明确的风险集合筛选，在筛选后计算总数和分页。

窗口缺失任务需明确提供“窗口不可计算”入口或提示，不能因未进入逾期、临期集合而被解释为无风险。

任务搜索应覆盖全部授权快照记录，与风险筛选共同作用，再分页返回。若暂时保留当前页过滤，控件必须明确命名为“筛选本页”。

“查看证据”必须指向该任务与快照下真实可用的证据。证据能力未接通时应明确说明，不能保留原型里的演示提示冒充实际读取。

### 7.2 待办与最近调查

待办数量由服务端统计全部授权记录，不能根据列表第一页估算。“我发起的待审建议”“需修改的方案”等事项按实际业务状态定义，点击后进入相应记录。

调查员和审核人应看到各自可处理的事项。前端隐藏入口只改善体验，服务端继续裁定权限及审批操作资格。

待办与最近调查属于账号工作流信息，应明确标注范围。若未按当前快照筛选，不能让用户误以为它们全部属于当前快照。

## 8. 建议实施顺序

| 阶段 | 交付内容 | 验收重点 |
| --- | --- | --- |
| 第一阶段：工作台改版 | 紧凑范围栏、四项默认指标、优先任务区域、桌面布局、统一状态样式 | 当前范围与数值一致，主要内容优先可见，原有调查流程可继续使用 |
| 第二阶段：指标中心与配置 | 分类搜索、口径弹窗、首页勾选排序、配置保存、共享快照 | 页面切换保持范围，配置刷新后保留，新增目录项无需改动首页布局逻辑 |
| 第三阶段：业务数据补齐 | 待办汇总、最近调查、跨页搜索、人员负荷及字段质量专题 | 全量计数准确，任务筛选与分页一致，专题读取经过授权，入口对应真实记录 |

开发拆分不等于正式页面可以保留虚构数据。阶段性交付中尚未接通的区域应明确呈现未开放状态；完整设计落地需完成第三阶段相关能力。

## 9. 验收清单

- 工作台和指标中心显示同一快照的范围与数值。
- 修改范围、切换账号或授权变化后，不显示被误归属的旧结果。
- 首页默认四项，其他已接通指标可配置加入；指标增加不要求重写首页结构。
- 配置支持保存、取消、恢复默认及排序，刷新后保留当前账号和空间的设置。
- 指标中心分类与搜索能定位完整目录中的条目。
- 卡片进入与指标含义对应的任务、明细或专题。
- 正常零值、空样本、未生成快照、失败及不可计算清晰区分。
- “全部风险”不会混入普通任务；窗口缺失有明确提示。
- 搜索结果、总数与分页使用一致的筛选条件。
- 待办计数来自全部授权记录，最近调查链接到真实详情。
- 页面保留历史样本、参考年份及审批不等于执行等必要业务边界。
- 在 1280、1440、1920 像素桌面宽度下，主要操作可见且整页无横向溢出。
- 配置弹窗、搜索和主要按钮可通过键盘操作，焦点及状态标签清晰。

实施后按实际改动运行现有前端 lint、构建和相关浏览器测试；后端接口或计算改动运行相应回归，特别检查权限、时点可见性、缺失值与分页口径。该文档阶段未执行实现验收，不将建议写作测试通过记录。

## 10. 本次实际交付与验收（2026-10-13，北京时间）

按用户确认的六步顺序实施，范围仅覆盖本文页面及所需接口、测试和记录。

1. 共享快照：公共上下文维护编辑范围、已生效快照、汇总及读取状态；页面切换复用同一结果，输入变更、账号/空间/权限版本变化及失效读取清除旧结果，中止旧请求。
2. 工作台布局：紧凑范围栏、四项默认指标、优先任务、账号工作流和四个专题入口；长流程与限制折叠在范围说明，调查仍绑定生效快照。
3. 指标中心与配置：新增 `/metrics`，五项真实指标共用目录，支持分类、搜索、口径和对应明细入口；首页配置支持草稿、保存、取消、恢复默认、勾选与上移/下移，按账号和空间保存指标 ID 顺序，至少保留一项。
4. 任务能力：现有 `/tasks` 增加 `risk_state=risk` 和 `search`，风险/搜索先筛选再计算总数及分页；窗口不可计算有独立入口。新增快照任务证据读取，使用当前快照和持久化行编号定位，经过实时授权，仅返回掩码字段与程序计算。
5. 业务数据：待办按当前账号角色和实际协同状态全量统计并分页，最近调查复用运行列表；二者明确不按当前快照筛选。人员负荷复用快递员分组；质量页面和工具共用可见字段统计；近期接单/完成明细采用服务端相同的左开右闭时间窗口。
6. 验收：类型检查、生产构建、完整浏览器 25 项通过；最终专题类型整理后受影响的 5 项浏览器复查通过。后端 197 项中 184 通过、13 跳过；核心 152 项中 134 通过、18 跳过，无测试失败。最终任务证据定点读取调整后指标专项 9 项通过。

### 页面数据接口

下表路径均位于 `/api/logistics` 下；新增读取复用现有空间、角色、快照和时点授权，拒绝额外范围覆盖参数。

| 路径 | 当前能力 |
| --- | --- |
| `/snapshots/{snapshot_id}/summary` | 五项指标、统计窗口、版本和状态，沿用现有口径 |
| `/snapshots/{snapshot_id}/tasks` | `risk_state=risk` 为逾期与临期并集；`all` 仍为全部待揽收；`search` 搜索任务/快递员/AOI，最多 200 字，筛选后分页 |
| `/snapshots/{snapshot_id}/task-evidence/{row_index}` | 读取当前快照的真实可见任务字段和计算；行编号由任务或近期明细返回 |
| `/snapshots/{snapshot_id}/groups?dimension=courier_id` | 当前快照的人员积压、逾期、临期与完整分母占比 |
| `/snapshots/{snapshot_id}/quality` | 窗口、任务位置、接单 GPS、完成 GPS 的可用/不可用/适用分母/不适用统计 |
| `/snapshots/{snapshot_id}/recent?flow=recent_accepted` 或 `recent_completed` | 最近 60 分钟的已授权明细；支持 `search` 和分页，完成事件仅在当前时点可见时返回 |
| `/approvals/todos` | 分类 `my_pending`、`to_review`、`needs_changes`，全量授权计数、`kind` 筛选与分页，继续禁止自批 |
| `/runs?page=1&page_size=5` | 复用真实授权运行列表展示最近调查 |

首页配置存储键为 `scope:home-metrics:{workspaceId}:{account}`，只保存指标 ID 与顺序；无有效选择恢复默认，浏览器存储失败明确提示。未接入跨设备同步。
