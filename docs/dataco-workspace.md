# DataCo 数据源：网页与 Agent 接入

在“订单与支付分析”底部的数据源选择器中选择 **DataCo V5 · 订单与履约**，或展开“分析设置”。本次接入复用既有登录、会话隔离、历史任务、证据和报告保存流程。

## 已支持

- 三指标：去重订单数、商品件数、取消订单占比。全部包含取消、待支付、疑似欺诈等订单状态；取消仅指 `CANCELED`。
- 七维度：市场、地区、国家、客户类型、商品品类、配送方式、订单状态；一次一个分组维度，可以组合过滤。
- 五任务：查询、趋势、分组、两期比较、汇总。
- 日/月趋势，1—366天；等长、不重叠两期比较；日期区间左闭右开。
- 单数据源连续追问、删除过滤、改指标/日期、澄清；切换来源不继承另一个来源的条件。
- 图表、Markdown、SVG/PNG、ZIP证据包；国家/品类等长分组图仅显示目标值最高的12组并标注，完整表格保留全部组。

默认表单区间为2017-09-01至2017-09-30。源文件日期范围是2015-01-01至2018-01-31；不把用户日期静默缩到此区间。

## 示例

1. `2017年9月订单数趋势`
2. `只看欧洲市场`
3. `再按国家拆分`
4. `不限市场`
5. `换成取消订单占比`（模型解析；规则模式只需输入`取消订单占比`）

另外支持 `2017年每月订单数趋势`、`2017年9月按地区比较取消订单占比`。表单可直接指定多指标、全部登记的原始维度值。问题中显式的Top N/排序任务暂未开放，图表前12组只是显示规则，不代表完整排名分析能力。

`ANALYST_PLANNER=deepseek` 时使用现有有预算、用量记录和恢复的模型解析运行时，模型接收当前数据源的指标定义/枚举，候选字段仍由程序校验。规则模式支持上述基本句式，对未理解条件要求澄清。自然语言语义不能仅靠结构校验保证，最终生效范围始终显示。

## 数据库与口径

查询连接沿用服务器环境变量 `ANALYST_DATABASE_URL`，浏览器和模型不接收凭据。使用 PostgreSQL `REPEATABLE READ READ ONLY` 事务；业务SQL参数化，列名只来自本地白名单。单条业务查询8秒，数据版本核对每条30秒，任务180秒；没有任意SQL接口。

首次工具查询前核对 `dataco.orders/order_items/quality_issues` 的登记内容指纹，在同一事务快照内执行后续查询。指纹用于发现意外数据变更，不是对抗数据库管理员的安全机制；内容变化拒绝分析，需审核后登记新版本。当前每轮完整核对内容有数秒开销，后续可通过不可变数据版本存储优化，不跳过核验冒充快照不变。

业务聚合从订单明细出发，用 `COUNT(DISTINCT order_id)` 计算订单数和取消订单数，商品件数对命中明细求和。品类过滤仅保留命中明细，一个订单可属于多个品类，各组订单数不保证加和等于总体。全期取消率从全期分子/分母重算，不平均每日或各组比例。

零订单时两个计数为0、取消率为null。范围越界返回blocked_data，不补零。发布文件中的无记录日期只表示文件中记录数为0，不声明真实业务无订单或摄取完整。源时区未确认，按原始时间分桶，不提供相对日期；不伪造支付事件、支付水位或根因。

## 验证与运行

Python一般回归：`python -m unittest discover -s tests -q`。

`tests/test_dataco.py` 包含计划、澄清、来源切换、模型协议/恢复测试。设置 `DATACO_INTEGRATION=1` 且配置数据库URL时额外执行真实只读数据库测试，独立SQL核对数量/取消率、品类去重、年度月趋势、零订单、越界与只读约束。

在Scope目录设置 `DATACO_INTEGRATION=1` 后运行 `node --test server/dataco-workspace.test.mjs`，会从本地.env读取数据库URL，使用真实Python和数据库、临时会话库测试HTTP追问、回放、导出及用户隔离；强制规则解析，不调用收费模型。

`npm run lint` 和 `npm run build` 检查前端类型与生产构建。当前会话没有可用浏览器自动化连接，尚未完成网页视觉验收；新DataCo模型解析通过模拟响应测试，未新增收费模型联调。

服务已运行时刷新页面获取新构建；Python桥每次请求启动新进程，可读取最新适配代码。若改环境变量须重启后端。来源及完整导入说明见相邻项目 `docs/dataco-database.md`。
