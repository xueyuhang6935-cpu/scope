# 角色与权限

## 使用入口

在“系统设置 → 角色与权限”管理当前工作空间的成员。先注册成员账号，再由系统管理员填写账号并授予一个或多个角色。每个角色独立设置工厂范围、数据域和审批额度。页面顶部可以切换已加入的工作空间。

| 角色 | 权限 |
| --- | --- |
| 生产计划员 | 查看授权工厂、调查与方案试算、处理风险；完整工厂范围可手动扫描 |
| 采购／物流人员 | 查看授权数据，更新自己负责事件的交期信息；不能转派事件 |
| 审批人 | 在授权工厂及金额额度内审批；不能审批自己发起的方案 |
| 数据管理员 | 在授权工厂、数据域内导入、复检和维护数据；规则维护另需规则域权限 |
| 系统管理员 | 管理成员、自动监测及审批规则；不自动取得业务审批权 |
| 只读成员 | 查看授权工厂与数据域的数据 |

数据域包括库存、采购、生产、质量和规则，用于文件数据及数据库表的读取、维护授权。业务风险、调查和审批按对应业务角色、工厂及额度校验。数据域并非风险计算字段级脱敏规则。

## 实施顺序与接口

1. 数据迁移：新增工作空间、成员、多角色授权、审批规则、审计和迁移标记表；文件批次、草稿、规则、当前记录以及分析任务绑定工作空间。
2. 统一鉴权：`backend/business_access.py` 按工作空间、角色、工厂、数据域、责任人及审批额度检查；一次操作所需条件必须由同一角色授权满足。
3. 业务接入：数据导入与下载、数据库预览、风险处理、调查试算、历史分析和审批均在后端校验，前端传入账号或角色不能代替登录身份。
4. 前端接入：成员编辑、角色范围、停用、审计、审批规则和工作空间切换；业务按钮根据当前权限禁用。权限定期刷新，已停用成员的页面内容隐藏。
5. 自动测试：覆盖角色组合、跨工厂/跨空间访问、规则域越权、审批额度、自我提权、最后管理员、授权版本冲突、停用与历史结果、旧数据迁移和物流责任关系。

接口位于 `/api/supply/access`：`GET /me`、`GET/POST /members`、`GET /audit`、`GET/POST /policies`。请求使用 `X-Workspace-Id`，文件下载使用 `workspaceId` 查询参数；服务器仍逐项检查成员资格与资源归属。

## 关键约束

- 新工作空间给创建者显式授予系统管理员、数据管理员、生产计划员；没有默认审批人。所有者身份不能绕过后续权限检查。
- 系统管理员不能给自己新增或修改审批授权，须由另一位系统管理员设置；不能停用或撤销最后一位启用的系统管理员。
- 成员及审批规则使用版本号防止覆盖他人的更新；变更保存操作者、时间和前后内容。
- 调拨审批必须覆盖来源和目标工厂。工作空间审批规则与原场景规则同时生效，采用更严格限制；规则变化会使旧方案需要重新核对。
- 默认是个人本地数据空间；接入数据库场景后可以选择场景空间。共享成员只能使用其授权空间，不能替换他人空间的场景。
- 文件的创建者仍保留用于审计，业务可见性由工作空间授权决定。对话仍归创建者私人所有，其数据查询受空间权限约束；权限撤销后不能读取原空间的历史分析结果。
- 数据库中没有直接工厂字段的关联表仅向同时拥有 A、B 工厂对应数据域读取权限的成员开放，以免关联数据泄露。

## 迁移与运行

应用启动自动执行兼容迁移。旧单角色授权只迁移一次；撤销后重启不会恢复。旧文件按创建者当时配置的场景空间或个人本地空间归属。旧全局规则保留原始记录，并复制到已有文件数据所属空间，后续各空间独立维护。

部署前备份身份数据库、业务 SQLite 数据库及 LangGraph 检查点数据库。当前使用现有单进程服务和 SQLite 锁；本次没有扩展为多实例分布式权限管理。审批后的实际 ERP/WMS 调拨执行、收货回写与业务闭环仍属于后续执行集成，不会因批准方案自动执行。
