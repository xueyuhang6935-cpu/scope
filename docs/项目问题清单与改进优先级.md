# Scope 项目问题清单与改进优先级

整理日期：2026-10-14（北京时间）。

本文整理本次项目阅读和问题检查的七类发现，记录影响、证据、改进建议及验收条件。当前产品范围为上海物流调查助手，旧订单支付分析和汽车供应链材料仅用于追溯。当前功能以 [README](../README.md)、[实施状态](logistics-execution/task-status.md) 和实际代码为准。

本文是问题记录，不表示建议已实施，也不改变原任务与验收门槛。知识库的详细分析见 [知识库现状问题与改进建议](知识库现状问题与改进建议.md)。

## 1. 总体判断与优先级

当前系统已经具备快照、确定性指标、后台调查、证据报告、连续对话和人工协同 Demo。优先需要补齐使用中的故障隔离与恢复，再同步工程验证，随后按实际需求推进模型评测和正式业务验收。

| 编号 | 问题 | 证据性质 | 建议优先级 |
| --- | --- | --- | --- |
| 1 | 单份异常成果阻断整个知识库列表与搜索 | 已隔离复现 | 高：直接影响已有成果访问 |
| 2 | 失效引用使会话受限，缺少移除与恢复入口 | 内容异常已隔离复现；撤权另有现有测试覆盖 | 高：直接影响会话继续使用 |
| 3 | 确定性调查的聊天入口仍依赖模型解析 | 无模型配置已隔离复现 | 高：基础调查入口受模型可用性影响 |
| 4 | 动态调查的质量与成本增量尚未证明 | 已有真实模型对照记录，本次未重跑 | 模型能力扩大使用前必须处理；T13 当前暂缓 |
| 5 | 知识检索覆盖不足，引用内容选择较粗 | 正文搜索已隔离复现；上下文裁剪已检查代码 | 中：影响查找和复用效果 |
| 6 | 全量读取、共享锁复算和全量消息轮询存在规模瓶颈 | 已检查代码，尚未容量压测 | 先测量，再按瓶颈处理 |
| 7 | 测试与新交互未完全同步，版本基线和正式验收未收齐 | 代码、Git 工作区及已有状态记录 | 版本交付前处理；正式验收按既定任务推进 |

## 2. 单份异常成果会让整个知识库打不开

### 现象与影响

知识库列表逐份读取并校验成果，只跳过无权限或不存在的记录。遇到内容或索引指纹校验失败时，整个请求返回错误。异常发生在搜索筛选之前，因此一份异常成果会阻断其他正常成果的列表和搜索入口。

### 本次隔离复现

使用现有 `PageIntegrationTests` 临时数据库夹具建立两份成果，将其中一份索引指纹改为异常值。

| 请求 | 结果 |
| --- | --- |
| 另一份正常成果详情 | HTTP 200 |
| 知识库列表 | HTTP 409 |
| 搜索不匹配的关键词 | HTTP 409 |

该复现证明异常出现后的影响范围，不代表正式数据库已经出现成果损坏。

### 改进建议与验收

对当前有权限的异常条目单独记录和展示核查状态，正常成果继续可访问。覆盖索引补建与列表读取两个阶段；详情、下载和引用仍须完整校验，不通过更新指纹掩盖内容异常。

验收应确认：注入单份异常后，正常成果列表、搜索和详情仍可用；异常成果不能下载或引用；无权限成果的标题、编号、摘要和计数不泄露；异常有可追溯记录。

代码依据：[logistics_knowledge.py](../backend/logistics_knowledge.py)，`refresh_index()`、`read()` 和 `routes()` 内的 `listing()`。

## 3. 失效引用会卡住整个会话，缺少恢复入口

### 现象与影响

会话上下文会逐份校验引用成果。任一引用撤权、成果不存在或一致性校验失败时，会话可能返回 `restricted=true`，相关历史消息受到屏蔽，继续发送消息被拒绝。当前没有移除引用的接口与界面，用户无法通过现有引用管理操作恢复仍然合法的上下文。

本次在临时会话引用成果后注入该成果指纹异常，实际观察到会话受限，继续发送消息返回 HTTP 409。成果撤权导致会话和消息受限另有现有集成测试覆盖。

### 改进建议与验收

允许当前有效且有会话使用权限的本人移除失效引用。移除时校验会话归属、版本与处理中状态，不要求先成功读取已经失效的成果；提交后重新检查剩余引用及当前调查范围。

验收应确认：移除唯一失效引用后，剩余上下文合法的会话可继续使用；仍存在其他失效引用或调查撤权时保持受限；历史受限消息不因移除当前引用自动恢复展示；重复移除幂等，不修改原报告，不触发调查或工具调用。

代码依据：[logistics_chat.py](../backend/logistics_chat.py)，`authorize_context()`、`read()`、`reference()`、`message()` 和 `routes()`；现有撤权测试见 [test_logistics_page_integration.py](../backend/test_logistics_page_integration.py)。

## 4. 默认确定性调查仍依赖聊天模型

### 现象与影响

普通调查消息先由聊天模型理解并提出动作，再由后端创建确定性或模型调查。即使用户已经明确选择授权区域、完整参考时点和 `mode=deterministic`，当前聊天入口仍需调用模型解析。

确定性调查执行本身可以使用程序计算，但通过当前正式聊天入口发起普通调查，仍受聊天模型配置与服务可用性影响。

### 本次隔离复现

仅将临时测试应用的聊天模型配置设为空，发送带区域、参考时点和确定性模式的消息，然后手动处理后台消息。

| 检查项 | 结果 |
| --- | --- |
| 消息接收 | HTTP 202 |
| 操作错误码 | `model_not_configured` |
| 新创建调查数 | 0 |
| 最后回复 | 提示聊天模型尚未配置，当前消息未执行 |

本次验证的是无模型配置场景，未注入真实供应商网络故障。

### 改进建议与验收

为用户明确发起、参数齐全的确定性调查提供结构化提交入口，复用现有快照和运行服务。自由文本解释与复杂意图继续由聊天模型处理；不把任意文本自动当作发起调查的命令。

验收应确认：模型不可用时，明确提交的确定性调查仍能创建并交付指标、证据和模板报告；缺失或冲突参数要求用户确认；授权、幂等、当前版本和不重复执行约束继续生效。

代码依据：[logistics_chat.py](../backend/logistics_chat.py)，`process()`、`dispatch()`；[logistics_chat_model.py](../backend/logistics_chat_model.py)，`ChatModel.generate()`；[logistics_runs.py](../backend/logistics_runs.py)，`create()`、`step()`。

## 5. 动态 Agent 的增量价值尚未证明

### 已有结果

引用校验修复后的完整对照重跑记录显示：

| 稳定运行指标 | 固定流程 | 动态调查 |
| --- | --- | --- |
| 有效报告 | 6/9 | 3/9 |
| 已知 Token | 66,782 | 105,887 |
| 模型调用 | 15 | 32 |
| 工具调用 | 42 | 32 |
| 未知用量调用 | 0 | 2 |

动态已知 Token 高约 58.6%，另有两次未知用量。工具调用减少没有转化为总成本收益；动态调查还存在传输失败、报告协议拒收和整报告语义矛盾。

上述结果来自同一事件组的三个目标及小规模重复，不能推广为总体模型能力，也不能证明某次代码修复的因果收益。本次没有重新调用真实模型。

### 改进建议与验收

保持默认确定性流程及模型实验标记。按用户已确定的任务节奏，在恢复 T13 工作时分析失败类别，冻结代码、提示词、模型、案例与预算后进行公平对照；程序停止报告、协议通过与模型有效报告分别统计。

验收继续使用原门槛，不降低条件或排除失败运行。当前 T13 已按用户要求暂缓，G3 未通过；本文不构成重新启动该阶段的实施安排。

依据：[完整对照重跑](logistics-execution/t13-reference-rerun.md)、[当前实施状态](logistics-execution/task-status.md)。

## 6. 知识查找和引用内容选择偏弱

### 检索覆盖

当前搜索仅匹配标题、参考时点和确定性报告中的重点任务编号，未覆盖报告结论、限制和未解决事项。

本次从已保存成果中取出一条实际存在的限制文字进行搜索，结果为 0。完整报告已保存，不等于其正文可以被当前搜索找到。

建议先明确搜索字段，补齐报告正文关键词检索与命中片段，保留实时授权、稳定排序和分页；是否增加语义检索由实际效果决定。

### 引用内容选择

历史引用按固定顺序取前 20 个证据标识，再压缩工具结果；单任务快照证据会被压缩器跳过，工具结果通常只保留前三行。引用路径没有依据当前问题选择最相关的任务或人员证据。整个序列化上下文超过 48,000 UTF-8 字节时会停止处理。

因此，报告保存了完整证据，不代表模型在本轮回答中看到对应明细。该裁剪行为已检查代码，对真实回答质量的影响本次未验证。

建议补齐引用查看与移除功能，复用已有向指定本人会话引用的后端接口；指定任务追问应按权限读取原保存证据。裁剪时保留来源、时点、约束、限制和必要反证，并明确未读取范围。

验收应确认：正文关键词能命中；向已有会话引用不会新建调查；指定任务位于原工具结果前三行之外时，其授权明细可以进入上下文或明确提示未读取；失效或无权限内容不参与摘要、计数和模型输入。

代码依据：[logistics_knowledge.py](../backend/logistics_knowledge.py)，`listing()`；[logistics_chat.py](../backend/logistics_chat.py)，`inputs()`；[logistics_model.py](../backend/logistics_model.py)，`compact_evidence()`；[logistics_chat.py 上下文组装](../project/context/logistics_chat.py)，`build_messages()`；[KnowledgeDetail.tsx](../src/logistics/KnowledgeDetail.tsx)，`cite()`。

## 7. 全量读取与轮询存在规模瓶颈

### 已检查的实现

- 指标查询读取整个持久化快照，在共享数据库锁内复算后再筛选和分页。
- 知识库列表先扫描调查并补建索引，再读取、校验全部成果，最后筛选和分页。
- 智能助手约每两秒读取会话列表及当前会话全部消息；超过 100 条时继续翻页拉取，再查询相关调查状态。

这些工作量会随快照、成果和会话长度增长，分页暂未有效减少全部后端处理成本。本次没有容量压测，不能据此断言当前页面已慢或给出吞吐上限。

### 改进建议与验收

先用隔离数据库测量典型及较大数据量下的耗时、数据库读取次数、锁占用和消息传输量，再处理实际瓶颈。聊天可优先复用现有消息游标增量读取；指标和成果摘要优化必须绑定版本或指纹，并保留实时授权和内容一致性检查。

验收应比较相同数据规模与授权条件下优化前后的结果、排序、分页和性能；撤权后结果、摘要与计数同步受限。继续保持单应用进程，增加 worker 前先处理 SQLite、任务领取与检查点的并发边界。

代码依据：[logistics_metrics.py](../backend/logistics_metrics.py)，`LogisticsMetrics.query()`；[logistics_knowledge.py](../backend/logistics_knowledge.py)，`refresh_index()`、`listing()`；[Assistant.tsx](../src/logistics/Assistant.tsx)，`load()`；[协作约定](../AGENTS.md)。

## 8. 测试、版本基线与正式验收尚未收齐

### 8.1 浏览器测试与新交互不同步

范围工具栏已改为“调整范围”“配置指标”和抽屉内“应用范围”，部分现有测试仍查找“创建回放快照”“配置展示指标”，并假定区域输入直接可见。

该失配根据源码确认，已有工具栏修改记录也明确说明旧选择器未迁移。本次短时浏览器专项设置了 8 秒超时，实际停在 `page.goto()` 加载阶段，未运行到选择器断言；不能将该结果作为旧选择器运行失败的复现。

建议按新交互更新已有测试，保留区域、参考时点、非法年份不发请求、失败重试、取消不提交、撤权清除和不自动调查等业务断言，再执行受影响及必要完整回归。

依据：[ScopeBar.tsx](../src/logistics/ScopeBar.tsx)、[logistics-workbench.spec.ts](../tests/logistics-workbench.spec.ts)、[工具栏修改记录](../plan/20261014-150928.md)。

### 8.2 当前实现与 Git 稳定基线相距较大

检查时当前分支为 `feat/frontend-metrics-workbench`，存在大量已修改与未跟踪文件，包括物流后端、Agent 核心、前端页面、测试和文档。当前能力不能仅通过已有提交记录还原和核对。

建议交付前按可验证范围整理提交，排除配置秘密、运行数据库、依赖和生成产物，关联对应验证证据。本文仅记录工作区现状，本次没有提交或推送，也未检查远程备份情况。

## 9. 建议处理顺序

1. 修复知识库列表的故障隔离。
2. 提供失效引用移除与会话安全恢复。
3. 补齐不依赖聊天模型的明确确定性调查提交入口。
4. 同步已有浏览器测试，整理当前代码与验证基线。
5. 改进正文搜索、已有会话引用及指定任务证据选择；并行采集性能基线，按测量结果决定优化范围。
6. 按用户后续任务安排恢复模型评测和正式业务验收，继续保留原门槛与历史失败记录。
