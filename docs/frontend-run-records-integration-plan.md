# Scope 运行记录合并与业务页面调整方案

- 更新日期：2026-10-14（北京时间）。
- 文档状态：四个页面及必要接口已实施；验证结果见本次修改记录。
- 依据：[前端设计评审第 2.1 节](frontend-design-review.md)、当前页面代码及本次讨论。
- 目标：取消工作台，将概览与指标目录合并到风险中心；智能助手开展调查和后续处理，审批中心审核，知识库沉淀调查成果。数据中心、设置与账号的业务实现保持原样。

## 1. 调整原则

用户应围绕业务任务使用页面：在风险中心查看风险提醒和信息概览，在智能助手主动提出问题、开展调查和继续处理，在审批中心审核建议，在知识库查找和引用已归档的调查成果。

风险中心不承担调查发起或历史调查查找，风险项作为提醒，不跳转到智能助手。用户直接进入智能助手提出问题；打开页面、刷新或查看历史对话本身不触发新调查。历史对话承接之前的讨论和待处理任务，知识库承接已完成的调查成果。

每次调查的运行记录继续由后台保存，用于任务恢复、证据关联和问题排查。前端按业务需要展示进度、结论、证据、未解决事项和下一步操作。内部节点、调用参数、调用次数和原始 JSON 退出普通业务界面。

先迁移功能和入口，再移除原板块。不能仅删除导航，使现有调查、历史报告或协同操作失去访问入口。

## 2. 内容归属

| 内容 | 合并位置 | 展示方式 |
| --- | --- | --- |
| 当前风险、异常指标、重点事项 | 风险中心 | 风险提醒、影响范围、数据时点和相关证据 |
| 待办及处理状态 | 智能助手 | 当前调查旁展示需修改、待回执、待复核；待审核由审批中心承接 |
| 发起调查 | 智能助手 | 用户提出问题后，基于明确的区域、参考时点和快照开展调查 |
| 找回之前的讨论、继续处理调查 | 智能助手历史对话 | 打开已有会话，读取调查状态、结果及待处理事项 |
| 已归档的历史调查成果 | 知识库 | 可检索的报告、证据和处理结果，支持在新对话中引用 |
| 调查进度、结果摘要、未解决事项 | 智能助手 | 稳定的“当前调查”区域 |
| 完整报告、任务证据 | 智能助手 | 结果卡片及按需展开的证据 |
| 人工反馈、建议修改与提交 | 智能助手 | 对话及当前方案操作区 |
| 建议审核、批准与驳回 | 审批中心 | 审批中心内部的审核详情 |
| 内部跟进、回执、新快照复核 | 智能助手 | 按方案当前阶段展示操作和结果 |
| 原始执行日志、内部技术字段 | 维护人员的技术诊断途径 | 后台保留，不在普通业务页面展示 |

## 3. 风险中心承接概览与指标目录

相关代码：[RiskCenter.tsx](../src/logistics/RiskCenter.tsx)、[MetricCenter.tsx](../src/logistics/MetricCenter.tsx)、[TopicPanel.tsx](../src/logistics/TopicPanel.tsx)。

### 3.1 风险概览与提醒

- 原指标中心改为风险中心；以“风险概览”和“指标目录”两个页签复用原快照、指标配置、口径和任务明细。
- 增加 AOI 风险分布，继续提供人员负荷、字段质量、近期接单和近期完成专题，全部在风险中心内查看。

- 展示风险、异常指标、影响范围、重点事项、相关证据和数据时点。
- 风险提醒本身提供足够信息，用户无需进入智能助手就能理解哪里异常、可能影响什么，以及依据哪个时点的数据。
- 风险项不设置进入智能助手或发起调查的跳转；需要展开明细和证据时，在风险中心内查看。
- 保留展示所需的区域、参考时点及指标配置，明确历史回放、参考年份、样本范围和不可计算状态。

### 3.2 移除调查与历史入口

- 移除“发起调查”按钮、调查方式选择及风险中心直接创建运行的逻辑，调查统一在智能助手中开展。
- 移除“最近调查”，不在风险中心增加“查看全部”或分页历史调查列表。
- 移除风险中心底部“查看运行记录”入口。
- 之前的讨论和待处理调查由智能助手历史对话承接；已完成的调查成果由知识库承接。
- 上述入口在对应承接能力验证通过后移除，避免既有调查失去访问位置。

### 3.3 待办与处理入口

- 风险中心不再展示待办；需修改、待回执、待复核迁入智能助手的“当前调查与待办”，待审核由审批中心承接。
- 待审核事项进入审批中心的对应审核详情。
- 待修改、待回执、待复核事项进入智能助手的对应调查或方案处理区域。
- 打开待办只定位已有业务对象，不自动创建新调查。

## 4. 智能助手调整

相关代码：[Assistant.tsx](../src/logistics/Assistant.tsx)。当前页面已具备报告卡片、任务证据、草稿和提交审批按钮，应优先复用。

### 4.1 发起调查与历史对话

- 用户直接进入智能助手，提出调查问题后开展调查，不依赖风险中心按钮或风险跳转。
- 在智能助手中明确调查区域、参考时点和调查方式；条件不足时先补齐，确定后关联已保存的授权快照。
- 会话与调查保持同一份快照，不在读取会话或已有结果时另建不同快照。
- 打开页面、刷新、查看历史对话或重复打开已有调查，不自动创建或重新执行调查；请求重试继续复用既有幂等机制。
- 历史对话支持分页查找之前的讨论和调查，展示可识别的会话名称及调查状态，打开后读取已有结果并继续处理。
- 历史对话范围为当前账号可访问的会话，不按风险中心当前快照筛选；权限失效时隐藏受限内容并明确说明。
- 调查方式和状态使用业务用户易理解的表述，保留实验模型的必要说明。

### 4.2 当前调查区域

增加稳定的“当前调查”区域，避免用户只能在历史消息中寻找当前对象。

- 桌面：在聊天侧边展示。
- 手机：通过“当前调查”按钮展开，避免持续占据大量对话空间。
- 内容：调查问题、区域、参考时点、调查状态、结果摘要、未解决事项、最新方案和审核状态。
- 操作：根据当前阶段和后端返回的权限，展示补充信息、修改方案、记录回执、创建新快照复核等适用动作。
- 当用户讨论历史报告时，明确更新当前讨论对象，避免将旧报告与最新方案混用。

### 4.3 报告与证据

- 完整报告保留在结果卡片中，继续支持完整阅读和下载。
- 任务证据按需展开，以业务字段展示，不直接输出原始 JSON。
- 部分调查直接展示停止原因、已取得的结果和未完成事项。
- 移除“查看运行详情”，以及“已有证据和未完成项请在运行详情查看”等依赖旧页面的说明。
- 调查尚在运行、失败、取消、读取失败和权限失效需要明确区分。

### 4.4 当前方案与后续处理

- 最新草稿和当前提交版本明确区分，旧版本按需查看。
- 审核结果返回原会话；被驳回后在当前方案旁展示理由和修改入口。
- 批准后展示内部跟进、回执及新快照复核的适用操作。
- 反馈、审核、跟进和复核按当前阶段组织，不将全部历史表单串成一个长页面。

## 5. 知识库承接历史调查成果

知识库统一承接已完成的调查成果，优先复用现有知识库页面和报告、证据读取能力，不在风险中心另建历史调查列表。

### 5.1 归档与查找

- 将已完成的调查归档为可检索的报告，支持按调查问题或名称、区域、参考时点和归档时间查找。
- 展示调查结论、完整报告、相关证据、已记录的处理结果，以及成果的来源和限制，支持完整阅读和下载。
- 报告保留与原调查、快照、证据及相关方案版本的关联，不以摘要替代原始业务成果。
- 对已结束但只取得部分结果的调查，明确停止原因和未解决事项；无报告的失败或取消调查由历史对话保留状态，不包装成完整成果。
- 已归档报告可在新对话中作为资料引用；引用和阅读本身不重新执行原调查。仍需处理的方案、回执或复核定位到对应会话。

### 5.2 既有调查与权限

- 对没有聊天会话的既有调查，已完成的成果直接归档到知识库；仍在运行或需要继续处理的调查建立受权限控制的承接会话。
- 已完成成果的归档不要求补造历史聊天消息；归档及会话承接失败可重试，不重复创建调查。
- 知识库列表、检索摘要、报告、证据、下载和聊天引用均复核当前访问权限，归档不扩大原业务数据的授权范围。
- 保留参考时点、历史回放、参考年份和来源说明，避免把过去某个时点的结论当作当前事实。
- 人工陈述、实验模型、合成反馈、模拟回执及结果归因的必要标识随成果保留。

## 6. 审批中心调整

相关代码：[Approvals.tsx](../src/logistics/Approvals.tsx)、[ApprovalDetail.tsx](../src/logistics/ApprovalDetail.tsx)。列表区分待审核与审批历史，“核对建议与证据”在本页打开指定提交版本，旧版本只读。

### 6.1 审核详情内容

按以下顺序组织：

1. 当前提交版本、状态、发起人、区域和参考时点。
2. 建议内容与任务清单。
3. 相关报告和任务证据。
4. 上次驳回理由及可核对的版本变化。
5. 审核理由输入框和批准、驳回操作。

审核人无需经过聊天记录或技术日志即可完成核对。

### 6.2 版本与权限

- 明确正在审核的具体版本，不以“最新内容”自动替换用户正在核对的版本。
- 版本或内容变化后要求重新核对，防止对着旧内容批准。
- 继续复用既有后端权限、版本和内容摘要校验。
- 发起人不能自批；批准不等于执行。
- 界面操作是否可用由实际状态和后端返回能力决定。

## 7. 协同组件调整

相关代码：[Collaboration.tsx](../src/logistics/Collaboration.tsx)。该组件展示智能助手的方案状态、内部跟进、回执和复核；聊天承担反馈、草稿和提交，ApprovalDetail 承担审核，避免两套操作入口。

| 现有部分 | 调整去向 |
| --- | --- |
| 人工反馈、建议修改与提交 | 智能助手 |
| 建议及相关证据核对、批准与驳回 | 审批中心 |
| 创建内部跟进单、记录回执 | 智能助手当前方案区域 |
| 创建新快照复核、查看复核结果 | 智能助手当前方案区域 |

复用现有请求、状态和业务操作逻辑，仅作必要的组件拆分。移入智能助手时，应与已有聊天反馈、草稿和提交能力衔接，避免出现两套并行的方案生成和提交入口。

人工陈述保留“未经验证”标识；合成反馈和模拟回执保留演示标记；内部跟进不能表述为向真实物流系统派单，历史完成不能归因于模拟建议。

## 8. 调查与会话关联

相关代码：[logistics_chat.py](../backend/logistics_chat.py)、[logistics_runs.py](../backend/logistics_runs.py)、[api.ts](../src/logistics/api.ts)。

### 8.1 当前需要补齐的问题

旧工作台曾直接创建运行而没有关联会话。现由智能助手发起新调查，`POST /conversations/for-run/{run_id}` 幂等关联原调查；启动时承接仍在运行或需要处理的既有调查。知识库只索引已保存成果，不重新执行工具或调查。

### 8.2 新调查

- 由智能助手中的用户调查请求触发创建，并建立与会话的明确关联。
- 同时保持区域、参考时点、快照、调查方式及用户问题的一致性。
- 复用后台现有调查执行能力和请求幂等机制，不因页面加载、重试或会话恢复启动另一份重复调查。
- 会话创建或关联失败时，保留已保存的请求和调查标识，在智能助手中提供恢复或重试入口，继续关联原调查，不依赖风险中心历史列表找回。

### 8.3 既有调查

- 已有关联会话的调查，通过历史对话找回；已完成成果同时可在知识库中查找。
- 没有会话且已完成的历史调查归档至知识库；仍在运行或需要继续处理的调查关联已有会话或创建承接会话，并可从历史对话访问。
- 打开历史调查时读取已有状态、结果和证据；不自动重新执行调查。
- 关联已有会话或创建承接会话时，后端检查调查访问权及会话访问权。
- 归档与会话关联需要可重复执行且不重复创建对象，保留原调查和证据标识。
- 审核人通过审批中心读取授权方案，不因拥有审核权就默认获得发起人的私人会话访问权。

## 9. 导航、旧链接与技术日志

相关代码：[SupplyShell.tsx](../src/supply/SupplyShell.tsx)、[LogisticsPages.tsx](../src/logistics/LogisticsPages.tsx)、[App.tsx](../src/App.tsx)、[LegacyRun.tsx](../src/logistics/LegacyRun.tsx)。

- 主导航为智能助手、风险中心、审批中心、知识库及原数据中心；移除工作台、独立风险处置和运行记录。
- 默认进入 `/assistant`；旧 `/workspace` 转智能助手，带风险筛选或专题参数时转风险中心；`/metrics` 保留为风险中心路由。
- 更新风险中心、聊天、待办和审批列表中的旧详情链接及相关文案。
- 原 `/runs` 列表入口转到知识库的调查成果列表，并说明仍在运行或待处理的调查可从智能助手历史对话查找；风险中心不承接历史列表。
- 原 `/runs/{run_id}` 链接在授权核对后，按可访问的业务对象转到对应会话、知识库报告或审批详情；已归档且无需继续处理的无会话调查可直接打开知识库报告，不为跳转另建会话。
- 不存在、无权访问或没有可展示成果时明确说明；有处理需求的旧调查通过受控承接会话继续访问，旧链接不触发重新执行。
- 旧页面承接的业务能力全部迁移并验证后，再移除原业务页面实现。
- 后台继续保存运行、调用及审计数据，保留维护人员所需的技术诊断途径。
- 原始技术信息不在普通业务界面展示，本次无需额外建设复杂的日志管理模块。
- 维护身份与业务数据权分别校验，不因系统管理员身份就自动放开调查数据访问。

## 10. 建议实施顺序

1. 完善智能助手发起调查、历史对话及调查关联，补齐既有无会话调查的受控承接和失败恢复。
2. 补齐智能助手的当前调查区域、部分结果、方案状态和后续处理能力。
3. 建立知识库的调查成果归档、检索、报告与证据阅读及聊天引用，迁移已完成的历史成果。
4. 建立审批中心内部的审核详情，迁移审核操作。
5. 按职责拆分协同展示，消除重复的反馈、建议和提交入口。
6. 取消工作台，合并概览与指标目录为风险中心；移除调查、历史和待办入口，待办迁入智能助手。
7. 移除“运行记录”主导航和普通业务页面技术日志，处理旧链接。
8. 验证完整业务流程、历史对话及知识库成果访问，更新受影响的使用文档。

实施过程保持现有业务入口可用，待替代入口验证通过后再移除旧入口。
