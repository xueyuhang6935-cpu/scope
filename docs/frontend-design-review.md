# Scope 前端页面设计问题与改进建议

- 整理日期：2026-10-13（北京时间）。
- 评审对象：当前上海物流调查助手的工作台、智能助手、运行详情、审批中心、导航及移动端布局。
- 依据：2026-10-12 保存的桌面、手机测试截图，以及当前前端代码。
- 文档性质：设计评审与改进建议，尚未实施。此次未访问正在运行的网站，未进行新的浏览器测试或用户测试；测试截图包含隔离测试或接口替身数据，不代表正式业务记录。

## 1. 整体判断

当前前端最需要改善的是信息层级和业务流程的呈现。紫色主色、侧栏和登录页已经形成基础视觉风格，但业务页面仍带有开发验证界面的痕迹。

用户进入页面后，应能快速回答三个问题：当前调查发现了什么、正在处理哪份任务或方案、下一步应该做什么。现有页面将说明文字、技术记录和业务内容大量串联展示，增加了理解和操作成本。

## 2. 具体问题

### 2.1 运行详情把用户需要的内容放得太靠后

**问题表现**

- 页面先展示运行编号、节点、模型与工具调用次数、持久化事件和大段 JSON，之后才展示报告、人工反馈及审核。
- 执行事件逐条展开原始数据，模型计划、观察与报告也通过 JSON 展示。
- 调查过程越长，报告和下一步操作距离页面顶部越远。

**用户影响**

用户需要判断“发现了什么、接下来做什么”，却必须先阅读或跳过大量技术信息。运行状态虽然完整记录，但缺少面向业务的结果摘要。

**改进建议**

- 顶部优先展示调查状态、结果摘要、重点任务、未解决事项和下一步操作。
- 将报告、任务证据、协同处理和执行记录组织成清晰的区域或页签。
- 执行日志、调用参数和原始 JSON 默认折叠，保留按需查看能力。
- 将内部节点名称转换为业务阶段名称；完整编号和技术字段放入详细信息。

代码依据：[运行详情](../src/logistics/Runs.tsx)。

### 2.2 工作台首屏更像操作说明书

**问题表现**

- 流程介绍、历史数据说明、范围表单和调查方式占据主要空间。
- 三个核心指标排在较低位置，桌面截图中接近首屏底部，手机上需要继续滚动才能查看。
- 页面说明、表单、指标和任务清单主要纵向排列，缺少突出当前风险的布局。

**用户影响**

工作台难以让用户快速了解当前范围和风险情况。第一次使用需要读说明，重复使用仍要经过相同的大段内容。

**改进建议**

- 将区域、参考时点和快照状态收敛为紧凑的范围栏。
- 在快照就绪后优先展示积压、逾期、临期指标及重点任务。
- 将流程介绍和详细数据限制放入可展开的说明区，保留必要的“历史回放”和“参考年份”提示。
- 按当前阶段突出一个主要操作，例如查看风险、发起调查或继续处理已有调查。

代码依据：[工作台](../src/logistics/Workbench.tsx)。

### 2.3 聊天页缺少稳定的当前调查与当前方案位置

**问题表现**

- 报告、草稿各版本、审核通知都放在消息流中。
- 多条消息重复展示“查看运行详情”和限制说明。
- 历史对话名称区分度较低，列表中容易出现“物流对话”加序号的记录。
- 聊天持续后，当前讨论对象、最新草稿和可提交版本需要在历史消息中寻找。

**用户影响**

用户容易混淆历史报告与当前报告、旧草稿与最新草稿，也难以快速回到当前待处理对象。

**改进建议**

- 桌面增加稳定的当前任务摘要区域，展示区域、时点、选中任务、最新草稿和审核状态。
- 手机提供“当前任务”或“当前方案”入口，避免占用整屏对话空间。
- 历史版本和已处理通知折叠；最新可操作草稿明确突出。
- 用调查问题或区域、日期生成有区分度的会话标题。
- 保留消息来源和重要限制，但减少相同说明在每张卡片中的重复展示。

代码依据：[智能助手](../src/logistics/Assistant.tsx)、[聊天样式](../src/logistics/logistics.css)。

### 2.4 审批中心没有形成独立的审核体验

**问题表现**

- 审批列表主要提供“核对建议与证据”入口，点击后进入运行详情。
- 审核人需要在包含日志、调查和协同记录的长页面中定位审核内容。
- 列表缺少明显的待审核优先入口和状态筛选。

**用户影响**

审核人无法围绕当前方案集中核对任务、依据、版本变化及驳回原因，操作路径较长。

**改进建议**

- 提供专门的审核详情，集中展示建议内容、任务清单、相关证据及当前版本。
- 展示前后版本差异和此前驳回理由，帮助审核人确认实际修改。
- 明确放置批准、驳回和理由填写区域；以当前权限和方案状态决定是否可操作。
- 审批列表增加待审核、已批准、已驳回、已失效的状态筛选。
- 保持既有跨账号、版本和内容摘要校验；界面重组不改变后端审批规则。

代码依据：[审批中心](../src/logistics/Approvals.tsx)、[协同处理](../src/logistics/Collaboration.tsx)。

### 2.5 导航展示的能力与实际开放程度不一致

**问题表现**

- “风险处置”“数据治理”等入口仍存在空壳或尚未接通的内容。
- 上传文件、业务接口及通知保留了不可用控件或“尚未接入”的说明。
- 业务导航对不同角色展示的范围较宽，进入部分页面后才提示权限要求。
- 登录页仍使用“供应链智能助手”和“供应链任务”文案，业务页面已经使用“物流调查助手”。

**用户影响**

用户可能把未开放功能理解为故障，也难以建立对产品范围和自身可操作能力的稳定认识。

**改进建议**

- 根据已开放能力和当前角色组织导航，将常用且可操作的入口置于主要位置。
- 尚未开放的入口可暂时移出主导航，或集中明确标识，避免反复进入空页面。
- 区分“功能未开放”“当前账号无权限”“当前没有记录”三类状态，并给出相应说明。
- 统一登录、注册、账号和业务页面的产品名称、图标及介绍文案。
- 前端导航仅用于改善体验，资源权限继续由后端裁定。

代码依据：[应用导航](../src/supply/SupplyShell.tsx)、[物流页面分发](../src/logistics/LogisticsPages.tsx)、[登录布局](../src/components/AuthLayout.tsx)。

### 2.6 风险和状态的视觉区分不够

**问题表现**

- 普通、逾期、待审核、已驳回等内容大量使用相似的灰色文字和白色区域。
- 不少业务状态以正文形式显示，缺少便于扫读的状态标签。
- 主操作、次操作和信息入口的视觉层级不够明确。
- 工作台指标卡片选中描边存在蓝色默认值，与页面紫色主色不一致。

**用户影响**

用户需要逐行阅读才能区分风险、状态和可执行操作，页面的视觉重点与业务重要程度不完全一致。

**改进建议**

- 为风险、审批、数据不可用建立统一的颜色与文字标签，不能只依靠颜色表达含义。
- 每个区域突出当前主要操作，弱化次要动作和详细信息入口。
- 统一选中、聚焦、禁用、错误等交互状态的视觉规则。
- 用数字、风险标签、摘要和动作形成清晰层级，减少重要状态埋在普通说明文字中的情况。

代码依据：[业务通用样式](../src/supply/supply.css)、[物流样式](../src/logistics/logistics.css)。

### 2.7 手机布局完成了纵向适配，但操作效率仍然低

**问题表现**

- 顶栏包含标题、说明、空间名称和多个操作，占据较多屏幕高度。
- 三个指标卡片逐张纵向排列，指标区域较长。
- 运行详情和协同处理形成很长的页面。
- 任务表格需要横向滑动，状态、等待和逾期分钟等关键字段可能位于屏幕之外。

**用户影响**

布局能够容纳内容，但用户查看风险或推进处理仍需要频繁滚动、横向移动和寻找操作位置。

**改进建议**

- 简化手机顶栏，详细空间和模式信息放入可展开区域。
- 使用紧凑指标布局，减少重复说明。
- 手机任务清单改为卡片，优先展示任务编号、风险状态、逾期分钟和主要操作。
- 反馈、审核、回执与复核按当前阶段组织，已完成内容按需展开。
- 在不同屏幕尺寸下检查主要操作的可见性、触控尺寸及滚动体验。

代码依据：[工作台](../src/logistics/Workbench.tsx)、[运行详情](../src/logistics/Runs.tsx)、[业务布局样式](../src/supply/supply.css)。

### 2.8 搜索只过滤当前页，容易造成查找误解

**问题表现**

- 工作台、审批列表和运行列表中的部分搜索在前端过滤当前页结果。
- 页面已经存在当前页搜索提示，但用户查找具体任务或建议时仍可能忽略这一边界。
- 搜索后没有匹配项，并不代表全部授权记录中不存在该对象。

**用户影响**

用户可能将当前页未找到误认为记录不存在，需要逐页查找才能确认。

**改进建议**

- 提供覆盖全部授权记录的服务端查询，搜索与分页使用相同筛选条件。
- 保留当前页过滤时，明确命名为“筛选本页”，并区分本页无匹配与全范围无结果。
- 明确展示搜索范围、匹配数量和清除筛选入口。

代码依据：[工作台](../src/logistics/Workbench.tsx)、[审批中心](../src/logistics/Approvals.tsx)、[运行列表](../src/logistics/Runs.tsx)。

## 3. 建议实施优先级

以下为设计改进顺序建议，不代表已经排期或获得实施授权。

| 优先级 | 改进项 | 预期效果 |
| --- | --- | --- |
| P0 | 重组运行详情，前置结论和下一步，折叠技术记录 | 用户能快速理解调查结果并继续处理 |
| P0 | 建立独立审核详情 | 审核人集中核对方案、证据和版本变化 |
| P0 | 聊天页增加当前任务与方案摘要 | 长对话中仍能定位最新对象和可操作版本 |
| P1 | 调整工作台首屏，压缩范围设置和说明 | 优先看到范围、指标和重点任务 |
| P1 | 整理导航、未开放入口及产品文案 | 产品范围和角色能力更明确 |
| P1 | 优化手机顶栏、任务展示和分阶段操作 | 减少滚动和横向查找 |
| P1 | 改善跨页搜索 | 减少“未找到即不存在”的误解 |
| P2 | 统一风险标签、按钮层级和交互样式 | 提升扫读效率和视觉一致性 |

## 4. 改进后的核对重点

- 调查详情顶部能看到结果、重点任务、未完成事项和当前可执行操作。
- 技术记录可按需展开，业务操作无需穿过长日志区域。
- 聊天中能明确识别当前调查、最新草稿、提交版本和审核结果。
- 审核人可以集中核对建议与证据，版本变化和驳回理由清晰可见。
- 导航和空状态准确区分功能未开放、无权限、无记录及读取失败。
- 手机优先展示风险状态和关键时长，主要操作易于到达。
- 搜索范围和结果数量明确，不将本页无匹配呈现为全范围无记录。
- 调整界面后继续保留历史样本、参考年份、实验模型、人工陈述及审批不等于执行等必要业务边界。
