# 调查编排、方案试算与业务审批

本轮已接通风险事件 → 调查与证据 → 调拨／加急／组合试算 → 人工审批 → 编排恢复。业务记录存入 PostgreSQL `sc`，权限及审计存入本机业务 SQLite，LangGraph 使用独立的 `supply-graph.sqlite` 保存运行位置。

## 如何使用

1. 在“数据接入”保存模拟数据库场景，例如 `supplier_delay` 或 `partial_transfer`。风险页设置计算天数为 3，点击“立即扫描”。
2. 打开风险详情，在“调查与方案试算”点击“调查并试算”。查看确定性事实、供应商待核实反馈、原始证据、工具轨迹及方案对比。
3. 在“系统设置 → 角色与权限”为另一位已注册账号授予“审批人”，选择相关工厂并设置审批额度。创建者初始拥有管理和调查角色，但不能自批；后续操作按实际授权校验。详情中的旧单角色授权入口仍兼容，多角色成员请使用系统设置管理。
4. 用另一账号登录，在“审批中心”核对方案数量、到线时间、费用、来源库存、内容摘要及原始证据，填写意见后批准或驳回。
5. 审批写入数据库后，LangGraph 恢复。批准显示“已批准”；驳回后自动重新调查并试算。查看方案或提交审批时发现方案失效，也会自动发起下一轮。页面显示重规划轮次和原因，新方案仍需另一位有权限的用户审批。重复提交同一审批不会产生重复决定。

“审批中心”的“获授权的协作风险”供共享成员查看事件调查；调查员可从这里发起试算，只读成员和审批人不能发起。账号无需切换或复制所有者的数据库配置。

`partial_transfer` 三天窗口的基准答案是缺口 400 件：调拨最多 250 件，费用 500 元；加急最多 150 件，整份报价 3000 元；组合覆盖 400 件，费用 3500 元，剩余缺口 0。金额和数量在后端均使用 Decimal。

## 编排与模型

图节点为 `collect → investigate → plans → approval（interrupt）→ finish`。数据缺失、无可行方案或模型异常时结束为“需人工核查”。提交接口返回调查编号，单个后台工作线程处理任务；等待审批不占用线程或长事务。应用重启会恢复本地工作空间的未完成调查。支持撤回；运行步骤尚未结束时返回忙碌提示，稍后再撤回。

`finish` 得到驳回结果后，宿主自动创建关联调查并再次执行 `collect`。方案失效走相同入口。每次新调查保留父调查、根调查、轮次、驳回意见和已拒绝方案摘要；旧调查显示“已自动发起下一轮”。默认最多自动重规划3轮（不含首次调查），`SUPPLY_MAX_REPLANS` 可设为0关闭，最大5轮。相同快照下已驳回的方案不可再次提交审批；没有其他可行方案或达到上限时转人工，不空转。

新调查沿用原发起人与原工厂范围，每次重新检查权限。场景、回放时点或计算窗口变化时要求人工重新发起，不自动扩大范围。创建下一轮和更新父状态在同一事务中提交，并使用固定请求编号去重；重启会恢复待重规划和已排队的子调查。每轮分别保留报告、方案版本、工具审计与模型调用预约。规则模式同样支持审批后的自动重规划。

默认 `SUPPLY_INVESTIGATOR=rules`：运行相同的确定性工具和 LangGraph，不调用收费模型，不伪装为模型输出。启用模型时设置 `SUPPLY_INVESTIGATOR=model`、`SUPPLY_MODEL`、`SUPPLY_MODEL_BASE_URL` 和 `SUPPLY_MODEL_API_KEY`（也兼容已有 `DEEPSEEK_API_KEY`）。地址必须为 HTTPS；密钥只在后端使用。

模型通过 `update_plan` 记录或修订调查步骤，结合结构发现、只读 SQL 和方案试算取证，最后提交带已读取证据 ID 的说明。工具错误、参数无效或报告引用尚未读取的证据时，宿主把错误反馈给模型，允许在剩余预算内调整计划并补查。计划版本显示在调查报告中，并写入工具审计。业务数值、费用、可行性、权限和审批决定始终由程序确定；供应商反馈保留“未经独立验证”的标记。模型输出只作为待核对说明。

实际工作流启用 SQL 工具时，每轮调查默认最多12次模型调用、120秒和24000个累计已报告 Token；配置及工具结果上限见 [Agent 只读 SQL 调查](investigation-sql.md)。同一工具与参数第三次出现时停止空转。预算耗尽、权限失效、模型网络失败或超时转人工，不自动重试结果未知的模型请求。用量未知显示未知；不伪造费用。模型调用前先记录尝试，崩溃重放不会再次自动计费。审批后的新调查有独立预算；整条链默认最多4次调查。测试使用模拟模型响应，未调用真实付费模型。

## 试算规则

- 调拨：目标物料版本一致；来源工厂必须可计算。用来源工厂完整 14 天期初及各次供需余额的最小值作为保守可调拨余量，再受线路容量、截止时间、到线时间和费用约束。缺少来源权限时不返回来源库存。
- 加急：移动原采购承诺数量到新到线时点，同时扣减原承诺，避免重复供给。仅支持尚未发运、收货和取消且计量单位一致的采购行。报价按整份计费，不自行按部分数量折价。
- 组合：比较单次调拨与单次加急的组合，再调用缺料计算器复算覆盖量、剩余缺口；不引入优化求解器。
- 候选方案保留不可行原因、来源证据、快照摘要、方案摘要、规则版本与有效期。有效期同时受场景报价／发运时点及创建后 24 小时限制。

## 权限与审批约束

所有接口均要求登录；写接口沿用来源校验。权限以工作空间、工厂和业务动作为边界，支持生产计划员、采购／物流人员、审批人、数据管理员、系统管理员与只读成员的多角色组合。所有者身份不绕过授权，系统管理员不自动取得审批权。数据访问另按数据域校验，授权修改有持久化审计，审批角色映射模拟规则的 `manager`。完整配置与迁移说明见[角色与权限](business-access.md)。

审批必须由发起人以外的已授权审批人操作，校验权限范围、审批额度、规则角色、每个动作数量／费用上限、方案版本及内容摘要。报告可能包含来源工厂证据，因此读取整份报告及审批需要覆盖调查时的完整工厂范围。无法覆盖范围的方案不会出现在列表中。

审批前重新读取同一场景快照，核对库存、需求、交期、报价及规则是否变化。摘要或回放范围变化、过期、不可行时禁止批准并要求重新调查。审批内容、人员、意见、时间、版本和摘要持久化；恢复节点读取已提交审批，不信任客户端恢复参数。

## 接口与部署边界

| 接口 | 功能 |
| --- | --- |
| `GET/POST /api/supply/business-access` | 查询权限、授权或撤销成员 |
| `GET /api/supply/business-risks` | 获授权的协作事件 |
| `POST /api/supply/risks/{id}/investigate` | 幂等发起调查 |
| `GET /api/supply/risks/{id}/investigations` | 调查、报告与候选方案历史 |
| `POST /api/supply/investigations/{id}/cancel` | 撤回调查 |
| `GET /api/supply/approvals` | 可访问的方案列表 |
| `GET /api/supply/plans/{id}` | 核对方案、有效性及审批记录 |
| `POST /api/supply/plans/{id}/decision` | 绑定版本和摘要的批准／驳回 |

启动安装 `requirements.lock.txt`。数据库迁移在首次使用及恢复时执行，需要对 `sc` 有建表和写入权限；`supply_demo` 仅查询。运行一个后端进程，不使用多个 Uvicorn worker。本地权限／监测配置、LangGraph 检查点与 PostgreSQL 业务数据需配套备份。升级多进程前需替换检查点并加入任务租约与统一权限存储。

本轮止于审批决定：不预占库存、不创建调拨单／加急单，不模拟收货、质量放行、执行结果核验或正式关闭风险。多个候选方案可基于同一库存试算，后续业务执行必须再次复核并原子预占。原有 `APR-001` 等固定演示详情继续作为示例保留；真实审批使用 `PLAN-…`。
