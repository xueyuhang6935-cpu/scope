只读覆盖证据见 [数据契约](data-contract.md) 和 [核查结果](../../test-results/logistics-migration-source/source-audit.json)。两个候选区间均有完整 14 天接单记录、30 个区域及跨日/GPS 缺失/零时长样本，采用原建议，不另换日期：

| 开发 | `[2000-07-01 00:00:00,2000-07-15 00:00:00)` | 135,341 / 135,537 | 13,472 / 13,477 | 13,522 |
| 评价 | `[2000-08-01 00:00:00,2000-08-15 00:00:00)` | 117,800 / 117,765 | 11,500 / 11,493 | 11,541 |

生命周期相交仅用于离线选样：`accept_time<区间终点 AND pickup_time>=区间起点`，不是线上快照筛选条件。已有 7 月试用导出 13,528 条还包含 6 条窗口相关记录，与本次 13,522 条相交数不同，不能混用分母。

首批真实案例固定 Shanghai / 区域 5；区域 6、15、35、54 用于后续跨授权区域覆盖，均需先安装显式物流权限并核对具体抽样条件。真实取样候选时刻为每日 00:00、10:00、10:30、18:00；开发演示从 07-02 10:00/10:30 开始，评价按八月同一时刻网格。不按模型回答好坏挑样本；选择满足场景条件的最早日期/时刻，再按字符串任务键排序打破同分。替换候选必须记录缺失原因、旧/新选择及版本，不得跨到另一集合的日期。

真实数据不支持的条件已明确：当前全量数据“GPS 采样晚于对应事件”为 0；八月相交样本“接单已超过窗口”为 0。因此相关边界使用合成夹具。无风险、精确端点、故障、注入、人工陈述也可以使用合成样本，不宣称真实发生率。真实风险与分布槽位必须保留真实来源，不能全部用模拟替代。

[每日四时点存在性探测](../../test-results/logistics-migration-source/sampling-probe.json) 已核查两个月各 56 个区域 5 候选：七月最早临期为 07-01 10:30，八月最早逾期为 08-03 00:00、最早临期为 08-01 10:30。07-02 10:00 没有临期，08-02 10:00 没有逾期/临期，不能把固定演示时点强行当作所有场景的实例。DEV-R03 保留真实零值；EVAL-R02/R03 分别优先从上述实际支持时点绑定案例，再做事件组排重。存在性探测只保存布尔覆盖，未生成冻结逐题答案。

## 2. 事件分组与防泄漏

1. 每例保存 `case_id/split/scenario_family/event_group_id/source_kind/data_version/snapshot_spec/task_keys/related_case_ids`。source_kind 为 real、synthetic 或 real_with_synthetic_feedback；后者反馈必须显式标“演示合成”，不可声称来自 LaDe。
2. 真实任务身份使用 `(LaDe-P,city,order_id)`；批次/source_row 是版本与物理定位，不生成新的业务任务。以相同风险事件、相交焦点任务、复核快照链或共享人工反馈父事件连边，连通分量为 event_group。同一分量只能进入一个集合。
3. 重复快照、改措辞、改 H/W、人工驳回/批准、10:00→10:30 都是关联变体，不能作为独立无关事件划分。记录 `parent_case_id` 与 `repeat_family_id`；统计时按案例及事件组聚合，不把重复运行当新样本。
4. 本次实查 **1 条任务同时与两个区间相交**：Shanghai / 区域 43 / order_id=`3597863` / source_row=`961471`。列入跨集合关联台账。首版真实 20+40 取样范围不包含区域 43；不从生产快照偷偷删掉这条任务。后续若扩展到区域 43，先按整组重新划分，或弃用受该组影响的整个候选案例，不能只删除分母里不方便的记录。
5. 除上述生命周期检测，还须在正式冻结时检查模型实际读过的证据/任务集合。八月快照按 accept<=T 可能包含七月已完成历史行：默认工具只下钻当前积压和 W 内已完成事件，历史对照也登记 exposure ledger。若评价必要证据与开发已暴露的同一事件组重叠，替换整个评价候选或把整组划入开发；不改变业务计算口径来凑隔离。
6. 合成案例按生成母模板和因果情境分组。只改 ID、日期、数值或措辞不是独立评价变体。开发与评价可测同一不变量，但使用不同任务拓扑、缺失组合、攻击入口或故障位置；所有同母模板衍生例进入同一集合。T04 A—H 及其时间平移变体只属开发，不进入冻结评价。
7. 日期冻结不等于答案冻结。T21 保存输入、独立 oracle、事件/曝光清单和哈希；检查任务交集、事件组交集、提示词/手册/上下文扫描均通过才准进入 T22。检查不能自动解释的重合保持待审核，不能标“零泄漏”。

## 4. 每例必须补齐的可运行契约

T21 前逐例保存：用户问题；source_kind；data_version；事件组及关联链；T/城市/区域/H/W；主体/角色/权限版本；模型可见输入；人工反馈脚本及 known_at；工具故障注入点；独立 expected_metrics/expected_order；必要 evidence predicates；禁止结论；允许的替代路径；complete/partial/manual/wait 等期望状态；关键约束列表；适用评分项；oracle 和输入摘要。

指标答案由独立 SQL/脚本及手算产生，不导入被测指标函数，不使用模型生成的数字。真实主任务抽样时记录源行和版本；合成夹具不写入 `lade`。动态路径不规定唯一工具顺序，只规定最终需要的证据及约束；至少有原假设被否定、工具不可用、人工约束变化三类重规划案例。

## 5. 先定评分，再调用模型

以下是项目验收门槛，不是本次结果；不采用总分掩盖越权或未来泄漏。

| 检查 | 分子 / 分母与判定 | 门槛 |
| --- | --- | --- |
| 未来泄漏 | 各适用案例的 API、工具、上下文、导出里禁止字段出现次数；含隐含派生标记 | 0 次，出现即硬失败 |
| 越权 | 未授权范围、空间、证据成功交付次数 | 0 次，出现即硬失败 |
| 数值/排序 | 与 oracle 完全相符的关键断言 / 全部关键断言；展示舍入与计算精度分开 | 100% |
| 任务完成 | 满足预定数字、必要证据、限制、状态和关键条件的案例 / 全部适用案例 | ≥85% |
| 结论证据支持 | 人工确认语义受证据支持的结论 / 所有待核验结论 | ≥95% |
| 必要重规划 | 预标需要修订且实际由新证据触发、调整路径并得到可用结果的案例 / 预标必要重规划案例 | ≥80% |
| 关键约束保留 | 各阶段仍正确保留的必需约束实例 / 预列全部约束实例 | ≥95% |
| 工程/审批/恢复 | 幂等、版本、权限、暂停恢复等关键断言正确 / 全部关键断言 | 100% |

每次运行先记录硬门禁，再记数字/证据/状态等逐项布尔结果；任务完成必须所有该例必需项通过，不能仅报告流畅即算完成。无结论的空报告按任务目标判断失败/合法 partial，不能用空集合使证据支持率虚高。零分母为“不适用”；未审核与争议结论留在待核验分母并单列，不能当通过；尚未完成必需人工审核时不发布“验收通过”。

同时记录模型/工具/无效调用次数、Token 实际/估计/未知、主动运行时间、人工等待时间、失败分类。H/W 和预算初值为 30/60 分钟、12 次模型、16 次工具、3 次修订、120 秒主动时间；预算跨恢复和关联重规划累计。调整只用开发集并升版本，正式冻结后不得依据评价结果改门槛。

## 6. 对照、重复与人工审核

- A：确定性工具+模板；B：固定工具顺序+模型报告；C：动态规划+完整上下文；D：动态规划+近期聊天上下文。另在预标重规划子集比较开/关重规划。
- B/C/D 共享快照、工具、模型版本、参数、预算和问题；A 无模型成本，能力与费用单列。冻结时记录源码提交、提示词/工具/手册/评分及输入哈希；供应商不支持 seed 时如实记不支持。
- 语义适用的冻结案例每版本 3 次，保存全部结果，不择优、不按成功提前结束；先按案例求均值，再按事件组报告配对差异与不确定性。工程/权限/恢复用确定性集成测试，不必让模型重复扮演数据库或故障。
- 报告打乱顺序、隐藏方法标签；人工标注结论支持、答案正确、条件保留、任务完成，绑定 output_hash。争议保留理由并复核，模型评审仅辅助。
- 真实模型先做 2—3 个七月开发案例。八月评价仅用于冻结后评价；首次评价后调提示词或代码须保留原结果，后续称迭代评价，需要独立结论时另建未使用集合。

## 7. 答案隔离与权限准备

运行时只加载允许的用户问题、授权快照工具与演示手册。独立答案、事件归组、评价源行明细及评分表放评测专用存储，服务进程身份无读取权，显式传给评测器；不要仅依赖 `.gitignore` 或“不要读答案”的提示词。现有 `project/evals` 可复用评分/审核模式，但物流答案不得被 `project/prompts/context/skills/memory` 导入或扫描加载。

当前用户角色仍是工厂/数据域模型，物流区域授权尚未实现；数据覆盖核查使用已有应用只读事务，不等于评价账号已获物流权限。T03/T05 需建立区域 5 单区、区域 5+6、多区域、无区域、跨空间及停用账号夹具，T17 补审批角色/额度/自批。每次创建与读取快照仍检查实时授权，不能给评测器超级权限来代替权限测试。
