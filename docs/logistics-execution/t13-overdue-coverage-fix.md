# T13 逾期覆盖误判专项修复

本轮仅处理“人员名单展示不全被误认为逾期归属不足”的问题，以及相应的数值判断和报告表达。未修改工具参数绑定、修订触发、预算、模型配置、业务数据或完整 ContextBuilder。

## 实际行为

- `backend/logistics_model.py` 保留工具原有 `truncated`，新增 `query_truncated` 与 `context_truncated`，分别说明查询分页和模型展示压缩。限制文字禁止编造未展示人员的任务和负荷，允许已有证据支持的判断。
- `project/agents/logistics_coverage.py` 从当前运行已授权的完整工具证据生成摘要；观察即使只展示当前页，也获得之前已保存页的逾期覆盖摘要。摘要不是完整历史观察，不引入未查询数据库数据。
- 核对运行、快照、指纹、参考时点、指标版本及可用的城市/区域；使用全局逾期分母，不把筛选后的 `total_rows` 当作分母。人员聚合按人员去重，任务明细按快照任务证据ID去重；聚合与明细不能相加，计数冲突、缺失窗口、不可计算或相关工具失败时标未知。
- `person_list_coverage` 表示已保存查询的人员名单覆盖；`ownership_coverage` 表示逾期归属覆盖，两者独立。部分明细只是数量下界；下界已超过全局一半可以确认过半，下界未过半不能据此否定该人员过半。可信人员聚合计数则可以单独判断，不要求完整名单。
- 观察和报告提示词要求指出缺失证据具体影响哪个目标。共同窗口等目标不会被强制追加集中程度结论。
- 新模型报告针对问题或计划目标含“集中/过半/一半”、且已有人员计数候选的情况要求 `overdue_assessment`。该触发是当前问题表达的轻量规则，不是通用意图分类器。旧报告和程序停止报告仍可校验读取。
- 报告结构化判断核对人员、计数、全局分母、判定和引用；未知集中程度不能对该目标宣称 `complete`。`claim_index` 指向对应的 observed 结论，程序根据已校验数字生成该句，防止“66.7%却写未过半”。错误进入既有最多一次模型修复，不开启新调查、不提高预算。
- 这不是所有自然语言结论的语义校验：其他报告句子、负荷完整性、根因和共同窗口判断仍可能错误。本轮不修复这些问题。

## 验证结果

- 专项覆盖测试10项通过：名单不全但逾期完整、部分覆盖已过半、未过半下界未知、分页去重、聚合与明细不重复相加、过滤不改变分母、时点/口径不一致、冲突、零与恰好一半、错误报告修复及目标未解不能 complete。
- 后端完整回归152项，无失败，13项跳过；最终目标范围后端模型/流程/修订33项通过，最终模型宿主7项通过。核心最终完整回归119项，无失败，18项跳过；离线原供应链协议24/24。编译和空白检查通过。
- 最终真实证据重放：[覆盖结果](../../test-results/logistics-overdue-coverage-final-replay/replay.json)。读取原v5的18份稳定性记录，其中17份存在工具证据，覆盖计算符合预期；1份原运行没有工具结果，保留未知，不补造证据。重放不改写旧记录或源数据库。
- 实施期间第一次专项回归因旧模拟模型不返回新增字段而失败；更新共享模拟报告夹具后通过，未放宽运行时校验。重放脚本第一版未处理固定方法无trace与无工具结果，修正读取逻辑后通过。

- 以上为内部定向检查，非独立人工盲审；没有重跑完整18次调查稳定性实验。新规则对数值关系提供确定性保障，但不能保证模型总能返回完整协议或回答样本负荷等其他目标。
