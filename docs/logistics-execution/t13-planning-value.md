## 开发案例与对照条件

四类均为明确标注的七月合成开发夹具，每例8条任务，不是正式业务发现，也不是T21冻结评测。参考时点为`2000-07-02 10:00:00`，区域5，H/W=30/60；原始记录经既有SnapshotService掩码后由真实工具查询。正式源库、账号和`.env`未修改。

| 案例 | 独立预期 | 必要证据检查 |
| --- | --- | --- |
| 人员集中 | 积压8、逾期6、临期0；6条逾期归001 | 人员分布及包含001的负荷证据；全人员负荷与筛选负荷均可，不限定唯一路径 |
| 多人共同窗口 | 积压8、逾期6、临期0；逾期分属6人，窗口结束09:50 | 人员分布及至少两名不同人员的逾期任务、相同窗口；只支持已观察子集共同窗口，不能推断未展示明细 |
| 空间缺失 | 积压8、逾期0、临期6；坐标不可用0/8 | 空间质量摘要与时效明细，缺失不解释为零风险 |
| 明细截断 | 积压8、逾期8、临期0；每人1条 | 明细覆盖8条，或完整人员聚合可复算逾期8；允许聚合替代分页 |

答案由标准库独立复算脚本生成，输入及答案不传入运行上下文。运行问题只描述调查目标与待检验假设，不提供人员ID或预期数字。人员集中/共同窗口使用完全相同问题；空间与截断使用对应目标，因而不能声称四例差异完全由数据单因素造成。

固定基线按`summary → courier distribution → workload → pending(page_size=2) → quality → model report`执行，不按结果改顺序。动态方法使用T11/T12正式LangGraph及执行器/心跳，模型选择工具并按证据修订。双方使用同一模型配置、工具、问题、输入及快照内容指纹，精简报告上下文同样最多显示3行并保留截断标记。两方法各用独立临时SQLite和预算家族，避免先执行一方消耗另一方预算；不改生产预算或绕过运行家族限制。

每方法每例一次；12模型/16工具/3修订/24000已知Token/120主动秒保持不变。固定基线为评测器直接调用工具和模型报告，数据库run仍为queued，不冒充后台完成；动态终态为真实执行器状态。三项报告必需取数计入动态成本。模型返回Token跨越24000时如实记录并停止，24000不是供应商硬计费上限。

## 两类可追踪路径变化

1. **反证改变方向**：[共同窗口运行](../../test-results/logistics-t13/live-v4/window-dynamic.json)。首步按人员分布查询，观察不支持单人集中；计划v2增加逾期时效明细，真实执行并返回两名不同人员的同窗口任务。空间缺失案例还从质量不足转向时效查询，但先查overdue返回空，后改due_soon，属于保留的效率失败。
2. **截断改变覆盖方式**：[人员集中运行](../../test-results/logistics-t13/live-v4/courier-dynamic.json)。人员分布首查2条且被截断，计划v2增加分布第2页，后续实际执行。截断案例增加聚合分页并实际执行两页，但仍未覆盖全部任务就达到Token上限。

所有最终已保存修订触发均由原始观察及工具结果重放`revision_triggers`复算一致；工具/参数变化与新增步骤单列，状态pending改completed不算路径改变。对照表记录修订后新增/改变步骤是否真的执行，不把未执行的新计划当作调查能力。此为确定性触发重放，不等于同一真实模型重复运行稳定成功。

## 失败分析与辅助语义复核

本次Codex对三份固定模型报告逐条结合原始证据复核；**不是独立人工盲审**，不发布正式语义达标率。25条结论中23条主要事实有证据支持，2条表述需修正：人员集中第4条将分组逾期share=1.0解释为个人积压分母，但该分布份额以全快照逾期6为分母；共同窗口第1条将recent_accepted误称“近期待接”，应为“近期接单”。共同窗口报告标complete却仍把目标中的共同窗口调查留在下一步，也不算完整目标完成。程序partial不纳入模型语义成功样本，空报告不以零分母虚构成功。

动态的主要失败是过度分页与修订：将明细每页2条扩散到分组/负荷查询，在已能回答局部目标时继续补排名；修订计划越来越长，调用输入累计Token快速超过上限。部分反证仍过于保守或与目标不直接相关，空间缺失案例先查零逾期再改临期；提示词调整未消除这些行为。基线本身也有份额口径、目标完成和传输失败问题，不是无误金标准。

已实施两项针对证据/协议的修正：模型精简任务视图保留已在T可见的窗口起止时间，便于检验共同窗口；规划/观察提示词要求简短描述、独立可检验假设，区分缺失与反证，常规样本限制不应触发无效修订。没有修改权限、扩大预算或加入开发答案。
