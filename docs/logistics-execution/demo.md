# 揽收风险调查 Demo

当前演示快照、调查、证据、人工反馈、审批、内部回执和新快照复核。复用 T01—T12 的真实接口；协同记录保存在当前业务 SQLite，刷新或重启可继续操作。按用户要求暂缓 T13 规划增量验证；G3 未通过，模型调查作为实验选项。

## 启动与演示

在 `Scope` 目录执行 `npm run dev`，打开 `http://localhost:3003`。本机服务已运行时直接访问，避免重复启动。

1. 使用已有调查员账号登录。当前本地测试登录方式见 [单空间与角色](single-workspace.md)，新注册账号仍需管理员授权。
2. 在工作台选择已授权区域，建议区域 5、参考时点 `2000-07-02 10:00:00`，点击“创建回放快照”。
3. 查看样本内积压、逾期、临期三指标；点击卡片展开任务与等待时长。
4. 默认点击“启动确定性调查运行”。后台保存真实工具结果、证据和模板报告，并跳转运行详情。
5. 在运行详情展开工具或任务证据，下载 Markdown 或打开报告页面。关闭页面后可从“查看调查记录”重新进入已保存的运行。
6. 如需体验模型规划，在已创建快照下把“调查方式”改为“模型调查（实验）”，填写问题后启动。观察保存的计划、工具、观察和报告；预算停止、请求失败或部分报告按实际状态展示。
7. 在完成或已保存部分结果的运行详情，进入“人工反馈、审核与复核”。选择“分析约束”，输入“演示约束：先核查两条任务”，将任务上限设为 2 后保存。合成反馈默认明确标记；“人工陈述”始终未经验证。
8. 点击“生成待审建议”。建议由程序从报告重点任务生成，绑定快照、证据和内容摘要；没有基础模板报告时先用运行详情的“生成基础报告”。
9. 通过右上角账号菜单切换到测试账号2（审核人），进入“审批中心”，打开建议，填写理由后驳回，例如“先核对窗口，再联系快递员”。发起人即使同时拥有审核角色也不能自批。
10. 切回测试账号1（发起人），在原运行把核查方式改为“核对窗口与现场约束”，修改说明后生成 v2。新版本显示前版驳回原因；相同被驳回内容不能直接重新提交。
11. 切换审核人核对 v2 后批准，再切回发起人。批准只记录决定，此时未执行；发起人单独点击“创建内部跟进单”。
12. 填写回执说明，默认勾选“模拟回执（不代表真实执行）”，保存。取消模拟标记时须提供外部来源编号，保存状态仍为“人工报告已执行，待外部核验”。
13. 选择更晚参考时点，例如 `2000-07-02 10:30:00`，点击“创建新快照并复核”。后端固定原批次与授权范围，新快照再经过 T 时点掩码。查看旧风险队列的完成/待揽收变化和新流入指标；历史完成不归因于模拟建议。

模型选项会调用服务端已配置的模型并产生用量；未配置时显示后端错误，不自动切换模式或重复提交。相同页面中对同一快照、同一问题的手动重试复用幂等键，修改问题使用新请求；任务家族累计预算仍由后端控制。模型输出不承诺稳定成功，基础模板报告与模型报告分开展示。

## 范围与后续

- 真实输入为已导入的上海 LaDe 历史样本，2000 年仅为参考轴。指标和风险结论限于样本，待揽收任务不读取未来完成信息。
- 本版人工约束用于建议修订，尚未接正式 ContextBuilder 或物流审核图的 interrupt/resume；不会自动恢复已停止模型。智能助手聊天发送仍未接通，从工作台启动调查。
- 反馈使旧待审建议失效；审核校验协同版本、建议版本、内容摘要、快照和实时权限；最后一次相同操作重复提交返回原结果。撤销审核权后不能据旧批准创建跟进单。内部跟进单与回执不会调用外部派单 API。
- 复核要求同一批次、区域、源版本、指标口径及更晚时点，原可见任务不能缺失；统计覆盖全队列，页面任务变化只展示前20条并标记截断。没有回执不能进入复核；未执行回执仍可做历史样本观察。
- 下一版完善上下文、模型反馈与审批图恢复，保留当前落盘协同契约；T14—T20 的正式实现和对应验收另行推进。
- 保留 T13 真实对照结果，后续恢复质量与成本优化；本版演示完成不代表 T13、T24 或 G3—G6 已通过。

## 接口

- `GET /api/logistics/runs/{run_id}/collaboration`：读取状态和当前可操作权限。
- `POST /api/logistics/runs/{run_id}/collaboration/{action}`：操作为 `feedback`、`propose`、`decide`、`followup`、`receipt`、`review`，均需 `version`，不接受客户端范围覆盖。
- `GET /api/logistics/approvals?page=1`：读取已授权区域建议的最新版本，逐项重新核对权限。

反馈、决定、回执和复核有版本记录、操作者和时间；协同事件写入现有持久化运行事件流。为保持 Demo 简单，每运行最多50条反馈、20版建议，一张内部单、一次回执和一次复核；需要新轮次时建立新的调查。
