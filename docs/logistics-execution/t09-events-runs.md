## 持久化与订阅契约

`logistics_events` 以 `(run_id, seq)` 为主键。SQLite触发器在运行、工具调用及报告状态事务中保存事件，事务回滚同时回滚事件。SQLite串行写入与主键确保run内序号严格递增；重装触发器幂等，不依赖内存订阅者。

| 事件 | 触发条件 |
| --- | --- |
| `run_created` | 新运行落盘 |
| `stage_changed` | 运行状态或节点改变，包括排队、领取、完成与恢复 |
| `tool_started` | 工具调用审计创建 |
| `tool_finished` | 调用状态改变，包含失败或中断 |
| `report_ready` | 唯一结构化报告首次保存 |
| `run_failed` | 运行进入失败状态 |
| `run_cancelled` | 运行进入取消状态 |

事件仅含状态、节点、工具/调用/证据/报告标识和受控错误码，不复制原始数据、秘密配置或异常原文。工具证据仍通过独立授权接口读取。

- `GET /api/logistics/runs`：`page`默认1、`page_size`默认20最多100、`status`白名单。先按实时可读范围过滤，再计算总数与分页。
- `GET /api/logistics/runs/{run_id}/events?after=N`：每批最多100条，返回 `next_seq`、`truncated`及已保存报告是否就绪。分页游标只能向持久化序号前进。
- 同一路径 `?stream=1`：SSE事件名为 `run_event`，`id`为序号；重连时`Last-Event-ID`优先于`after`，只补发较新记录。无新增事件发送心跳。每轮复核会话及run/快照当前权限，失效发送`access_invalid`并结束；初始无权返回403。
- 页面按序号去重并排序，同时以2秒轮询补充持久化记录、工具审计与报告，网络恢复后可重新读取。订阅不承担运行调度。
- HTTP响应提供`X-Request-ID`及run路径的`X-Run-ID`；新run保存发起请求标识，后台工具调用继承该标识。旧记录该字段允许为空。

## 兼容与限制

- 后端重启后幂等创建事件表/触发器，并添加run和调用审计`request_id`列；不重建已有实体、不编造升级前事件。旧报告即使没有历史`report_ready`事件仍可读取。
- 单应用进程；首版列表先扫描过滤，事件每0.5秒读取。全市容量、多worker、长时间并发和真实源完整浏览器联调尚未验收。不能依据本次测试宣称这些场景通过。
- 旧PostgreSQL供应链集成13+18项保持跳过，不写入源任务、正式账号角色或本机配置。
- 当前为确定性基础报告，聊天发送、动态模型规划和人工审核仍属于后续任务。T10及后续保持未开始。已有后端需重启加载新接口与自动报告流程。
