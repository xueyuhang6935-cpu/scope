## 2. 19 个原始字段映射

**下列 19 列实际全部是 PostgreSQL `text NOT NULL`**；NOT NULL 不禁止空字符串。原始字符串不覆盖、不补值、不重编。空字符串转成 API 缺失状态只在受控投影中发生。

| 序号 | 实际字段名 | 标准含义/计算类型 | 快照可见条件 |
| --- | --- | --- | --- |
| 1 | `order_id` | 任务/包裹编号，字符串；官方说明 package_id 的实际 CSV 名称 | 已接单 |
| 2 | `region_id` | 区域字符串，与 city 构成授权键；不是街道名 | 已接单且区域授权 |
| 3 | `city` | 城市字符串，本批 Shanghai | 已接单 |
| 4 | `courier_id` | 匿名快递员编号字符串，不是系统成员或联系方式 | 已接单 |
| 5 | `accept_time` | 快递员接单时间，原文+参考 datetime；不是平台建单时间 | `accept<=T` |
| 6 | `time_window_start` | 要求窗口起点，原文+参考 datetime | 已接单，按接单时已知假设 |
| 7 | `time_window_end` | 要求窗口终点，原文+参考 datetime | 同上；未来承诺窗口可以已知 |
| 8 | `lng` | 任务停靠点经度，原文/可用时 numeric | 已接单、与纬度成对验证 |
| 9 | `lat` | 任务停靠点纬度，原文/可用时 numeric | 同上 |
| 10 | `aoi_id` | 兴趣区域编号字符串，不替代 region_id | 已接单 |
| 11 | `aoi_type` | 分类字符串，无官方代码表，不推断住宅/商场含义 | 已接单 |
| 12 | `pickup_time` | 实际完成时间，原文+参考 datetime；不以 GPS 时间代替 | 已接单且完成 `<=T` |
| 13 | `pickup_gps_time` | 完成附近 GPS 采样时间，可空原文/参考时间 | 完成 `<=T` 且采样 `<=T` |
| 14 | `pickup_gps_lng` | 完成附近 GPS 经度，可空 | 与采样时间/纬度整体门禁 |
| 15 | `pickup_gps_lat` | 完成附近 GPS 纬度，可空 | 同上 |
| 16 | `accept_gps_time` | 接单附近 GPS 采样时间，可空原文/参考时间 | 接单 `<=T` 且采样 `<=T` |
| 17 | `accept_gps_lng` | 接单附近 GPS 经度，可空 | 与采样时间/纬度整体门禁 |
| 18 | `accept_gps_lat` | 接单附近 GPS 纬度，可空 | 同上 |
| 19 | `ds` | **完成日期**，四位 MMDD 字符串；不是接单日 | 仅完成 `<=T`，不得用于选快照候选 |

实查缺失只出现在两组 GPS 三元组：接单三列各 654,425 个空字符串，完成三列各 441,333 个空字符串；其他原始列无空字符串。`ds` 全部四位且与 pickup_time 月日一致，无需给当前库补零。已有映射对在线预览整数展示的补零说明，不是修改本库文本的授权。

## 4. 时间语义与实查

原文严格 `MM-DD HH:mm:ss`。解析 `2000-` 加原文，校验格式和真实日历合法性，不做“小时较小则加一天”、不自动滚月、不按系统当前年补全。真实年份没有证据：批次 `actual_year=NULL/reference_year=2000/year_status=undisclosed`。参考值是无时区本地钟表时间；Asia/Shanghai 是应用展示约定，不把它说成来源已认证的时区。不能由 2000 推断星期、节假日、天气或真实年度。

## 6. 读取账号与 Agent 边界

本次所有 PostgreSQL 连接从启动参数 `default_transaction_read_only=on` 开始，主数据核查使用 REPEATABLE READ/READ ONLY，设置语句及锁等待超时。没有执行 INSERT/UPDATE/DELETE、DDL、导入、角色授权或应用启动。

| 身份/能力 | 本次实际检查 | 契约结论 |
| --- | --- | --- |
| 应用 `scope_app` | 可读 lade 三张表，也有 INSERT/UPDATE/DELETE；无 super/create role/create db/bypass RLS；源 SELECT 成功 | 用 READ ONLY 事务核查安全，但账号本身不是最小权限源读取角色 |
| 供应链 `scope_agent_reader` | 无 lade USAGE、三表读写权均 false；实际源 SELECT 被拒绝，SQLSTATE 42501 | 目前不能直接读 LaDe；保留该隔离，不给其补源表权限 |
| 现有网页管理预览 | 连接管理者可读完整历史任务；工厂范围不能代表物流区域 | 这是授权数据管理例外，不是模型工具或快照接口，不可被聊天/工具转发 |
| 物流区域权限 | 当前代码 business_roles 只有工厂/数据域等字段 | 尚未实现；区域筛选参数不等于授权，默认拒绝未配置物流授权 |

T03 实施前的实际操作清单（本次未执行）：

1. 安装独立后端源读取角色，例如 `scope_logistics_source_reader`，只授予连接数据库、lade USAGE、必要源表 SELECT；无源表写权、DDL 权、特权角色及可提权成员关系。凭证只在服务端配置，建议独立 `LOGISTICS_SOURCE_DATABASE_URL`，这是待新增配置而非已有功能。
2. 快照构建 Repository 显式使用该连接，所有源查询 READ ONLY 且参数化，关闭缺省回退到 `ANALYST_DATABASE_URL`。不存在新连接则明确不可用。批次来源及质量元数据只供受信宿主核查，不直接返回模型。
3. 验证新角色只读、不能写/DDL/SET ROLE 提权，Agent 角色仍不能直接读取 lade。区分源读取账号与快照/运行结果写入账号，应用业务存储不因此变只读。
4. 在既有工作空间成员/角色体系内新增明确城市/区域授权，先覆盖区域 5 及隔离测试账号；不能把 system_admin、data_admin 或工厂 A/B 隐式当作全物流授权。具体迁移实现归 T03/T05，与原供应链权限回归一起验证。
5. 物流 Agent 仅拿宿主绑定 snapshot_id，通过参数化工具读掩码内容。禁止任意 SQL、源表连接、原始预览、全量离线质量报告进入模型。创建、查询、证据、导出、恢复均实时复核权限。

角色安装和区域授权是后续功能准入门禁，不是 T02 未完成核查；用户仅授权本次 T02，故不擅自修改数据库权限或推进快照开发。
