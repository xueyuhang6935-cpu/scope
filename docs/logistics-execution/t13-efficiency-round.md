# T13：真实案例效率修复与配对复查

## 本轮固定契约

使用已保存的三个真实快照，不重新抽样；人员集中为区域5、参考时点2000-07-02 18:00，共同窗口和明细截断为12:00。三项目标同属一个区域日期事件组，不能算三个独立业务事件。空间缺失在当前抽样范围未找到，合成测试仅验证边界。

问题、固定顺序、预算与评分门槛保存于实验目录的`contract.json`，独立答案只供评分器读取。最终固定基线按目标预先确定顺序，不由模型决定分支：人员集中查汇总、人员逾期降序分布、领先人员负荷、逾期明细、质量（5工具）；共同窗口查汇总、人员分布、逾期明细、质量（4工具）；截断查汇总、逾期第1/2页（每页2条）、人员分布、质量（5工具）。领先人员参数只从实际排序结果提取，不读取独立答案。早期开发六工具通用基线保留，不能将其多查的无关负荷算作动态收益。

开发阶段每例每方法一次，稳定阶段每例每方法三次，共18次；失败保留、不择优、不成功即停止。两方法保持同问题、同snapshot_id/指纹、模型、权限、预算、报告证据压缩规则。每次运行使用独立隔离备份和同权限评测账号，不改生产预算家族。

门槛：关键数字与独立复算一致、无越权/未来信息泄漏；动态每例至少2/3取得必要证据并交付有效报告；至少两类证据驱动且修订后实际执行的有效路径变更可重复出现；收益为答案/证据提升或相当质量下成本减少。稳定阶段之前冻结代码、提示词、问题与评分，不根据稳定结果调整门槛。自动工具数字核对不能替代报告语义审核。

## 失败清单

| 触发证据 | 原动作 | 无效原因 | 最小修改 |
| --- | --- | --- | --- |
| 人员分布有数百行但逾期只有3条 | 反复扩大全人员分布与负荷页 | 目标只需要最大个人逾期数、全局分母和重点人员样本负荷；零风险人员不能补充此判断 | 按逾期降序取有效头部，定位后筛选人员负荷 |
| 明细第1页只含2条逾期 | 将每页2条沿用到分组与负荷、重复翻页 | 目标明细限制被错误推广；共同窗口所需少量明细未执行，预算已耗尽 | 固定基线查逾期第1/2页；动态允许足够聚合替代完整明细，分页页大小保持一致 |
| 参考年份未知、样本不等于运力等普通限制 | 再次扩展目标或反证修订 | 这些限制不与当前假设矛盾，不能要求调查根因、现场运力或全区域排名 | 普通限制写missing，修订只对应尚未解决的当前目标 |
| 模型上下文反复包含完整计划、每条任务证据及工具明细 | 规划、观察与修订输入不断扩大 | 同一任务在工具结果和snapshot_task中重复出现；观察只评估当前步骤 | 保留完整授权/协议校验；模型观察只发送当前步骤和工具结果，报告去除完整计划及重复任务证据 |
| 报告前累计已知Token超过24000 | 到硬上限后只能生成程序partial | 有路径变化但没有目标答案，不能视为增量 | 决策提示剩余预算；已知余量不超过6000Token或仅余1调用时停止新增模型观察/修订，补报告基础取证并收尾；保留硬上限与全部失败 |
| 新增预算提示放到问题末尾 | 观察步骤编号匹配受到尾部文字影响 | 调用链以末尾步骤编号定位当前步骤，模拟回归暴露协议失败 | 将约束提示前置，保留末尾步骤标识；回归验证当前步骤绑定 |
| 工具完整结果含全局denominator，压缩视图却未保留 | 模型将分组分母误认个人分母，再翻零逾期页 | 模型输入缺少直接澄清分母的字段；不能把此失败只归咎模型 | 压缩视图保留顶层denominator和页码，提示明确分组指标分母是全局同风险 |
| get_quality_summary返回unavailable但data存在，仅GPS不可用 | 模型已回答人员/窗口目标并输出complete，后端再次拒收 | 后端把工具内局部质量缺失等同整项取证失败；固定基线没有同样拒收，比较失真 | 仅真正错误或整项data缺失强制partial；局部质量缺失仍作为真实限制，是否完成以目标证据审核判断 |

历史8次方法运行保存在`logistics-t13-real/dev-v1`及`dev-v2`。其预算只保存累计已知Token，无法补算历史输入/输出分项，未知用量单列。新运行按规划、观察、修订（规划kind并结合调用顺序）和报告保存供应商prompt/completion/total回执及请求字节数；不保存原始密钥或请求配置，不虚构金额。

## 实验及审核记录

开发初版目录`test-results/logistics-t13-round-v1`保留本轮新增失败。第二版`round-v2`保留传输失败、报告协议失败和Token停止，不反复重试同一产物。

初版人员动态23300Token中规划2309、观察8195、修订3834、报告8962（两次报告包括协议修复）；窗口动态23180中规划2326、观察8236、修订8452、报告4166。观察与修订仍是主要消耗，不能只以报告输出长度解释成本。第二版截断在报告前已耗21952，报告4875导致总量26827，硬上限拒绝交付；因此最终开发版将收尾触发从4000改为6000，覆盖报告输入及输出，未增加24000硬上限。预留是调度策略，无法保证外部模型每次响应都不超估计；超限仍判失败。

第三版`round-v3`帮助定位全局分母丢失及GPS局部缺失被误判整项失败的问题；第四版验证修复后仍出现占位人员参数、修改已执行步骤、报告修复后Token停止和传输失败。这些结果全部保留。第五版只按目标精简固定基线，并修复带人工约束时步骤标识的同类尾部问题；不继续针对模型失败增加规则。最终开发及稳定版目录为`test-results/logistics-t13-round-v5`。稳定阶段在此版本之后冻结，不根据稳定结果改代码、问题、提示词或门槛。所有方法相同压缩报告证据；模型协议仍校验完整授权证据和完整计划，不能用压缩内容绕过校验。

## 审核、安全与验收结论

最终24次运行的114条报告声明已逐条审核，其中15条不通过。审核者为Codex内部复查，非独立人工盲审；结果与理由逐条公开。工具已取得的五指标、返回任务和人员分组独立复算一致，不等于自然语言声明及分母正确。程序停止报告只复述保存的汇总原值，不伪装模型目标回答。

三个保存快照的全部可见行另用标准库检查区域、接单/完成/GPS时点及隐藏完成字段，无越权/未来信息泄漏；逐次工具结果范围检查也为零异常。重点人员负荷独立逐行计数为可见42、完成39、积压3、逾期2、临期0、近期接单0、近期完成0。没有声称检查了未留存的供应商原始HTTP全文。

本轮验证与交付完成，但**未证明足以放行G3的稳定规划增量价值**：动态只有截断达到2/3，人员/窗口未达；关键声明和分母存在错误；整体有效报告少于固定，模型成本更高。两类可重复有效取证修订通过不抵消其他门槛失败。T13保持`in_progress`，G3不放行，T14不启动；不能通过增加预算、挑选成功或删除失败改变结论。

下一轮若继续，应先处理实际人员参数绑定、用全局分母判断过半、将目标证据缺口与普通限制区分、报告的证据范围/分母一致性；先明确新契约再跑，不扩大预算或展开T14 ContextBuilder。本轮不再修改冻结版。
