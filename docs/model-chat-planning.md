# 大模型聊天计划与澄清

启用 `ANALYST_PLANNER=deepseek` 后，聊天消息进入 DeepSeek 任务解析器。分析表单仍可直接提交结构化计划。普通聊天会消耗解析用量；只有调查意图才进一步进入动态工具选择。

处理流程：消息与结构化上下文 → 单次工具调用形式的候选字段变更/澄清问题 → 宿主校验 → 固定分析或动态调查。模型不直接执行 SQL，不填写指标数值，不取得数据库连接信息或 API 密钥。

候选变更逐项引用本轮原话；宿主只接受登记的意图、指标、渠道和设备，不接受模型指定快照。未修改的字段从同快照的待澄清候选或最近已接受计划继承。删除过滤必须有显式取消表达；日期由程序按固定 request_time、上海时区展开，不能悄悄迁就演示快照。

示例：

- “请分析近5天订单支付率” → 整体30分钟支付率。
- “只看活动渠道” → 继承日期、指标，增加渠道过滤。
- “再按设备拆分” → 保留渠道过滤，改为设备分组。
- “不限渠道” → 删除渠道条件，保留其他明确条件。
- 新会话“请分析近5天订单” → 具体询问指标；回复“支付率”后沿用原日期。

澄清不执行数据查询、不计执行轮数，也不覆盖已接受计划；模型调用仍计入会话100000 Token上限。单次解析最多两次请求（仅明确限流拒绝允许一次重试），每次最多45秒，整个解析阶段100秒。动态调查原180秒时限从计划接受后开始，解析请求数和Token占用本任务10次/20000 Token总额度。

`analyst_planning` 持久化解析输入签名、已提交模型响应、候选结果和用量。签名包括上下文、提示词、工具结构和模型配置。`analyst_model_calls` 中 `details.phase=planning` 区分解析/澄清；调查标为 investigation。未知调用结果/用量不自动重试，同会话停止额外模型请求。解析响应已提交后中断，恢复直接使用已提交响应，不再次计费。

网页显示合计模型用量及解析部分；“模型调用与预算记录”可展开审计。已登录用户可查询 `/api/analyst/model-calls?task_id=...&phase=planning`，结果按会话所属用户隔离。

验证：14项初始解析/故障回归测试；真实 PostgreSQL 验证解析持久化、预算合并和未知用量。2026-09-30 的六轮真实 DeepSeek 冒烟测试全部通过，共6次请求、7789 Token，逐轮输出保存在 `data/verification/chatverify_d4525589078b48b4816959596bdbbc76.json`。它是冒烟验证，不是未见保留集评测，也不代表所有自由表达都能正确理解。

当前范围仍为三指标、六意图、两个维度和自然日分析。模型语义映射可能出错，程序检查不能证明模型完全理解了意图；页面始终展示实际执行范围。尚不支持的日期表达、排除条件或业务指标会要求澄清或明确拒绝，不能近似执行。
